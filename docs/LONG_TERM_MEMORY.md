# 长期记忆与近期经历（桌面0.1.7）

## 怎么使用

1. 从旧程序托盘选择“退出并停止后台运行”，打开本完整目录中的dreamtalk-desktop.exe。
2. 正常私聊或群聊，明确告诉角色重要信息，例如“我叫小林，喜欢无糖咖啡”。正常回复成功后，在聊天顶部打开“长期记忆”核对；群聊可选择固定成员查看。
3. 可以搜索、加载更早记忆、查看原句与记录时间、置顶或停用条目。记错或偏好改变时在聊天中明确纠正，例如“以后改喝茶，不喝咖啡了”。旧条目保留来源并标为已有新记录，不删除历史。
4. 后续与同一角色聊天时，系统会提供核心信息及与当前问题相关的旧记忆；相关历史原句也可跨该角色参与过的私聊和群聊召回。无需重新导入角色卡或付费整理全部历史。
5. 问“你在忙什么”“刚才做了什么”时，角色还会参考自己实际亲历的近期活动；先按[自动活动说明](DIRECTOR_ACTIVITIES.md)设置角色初始地点并授权开启日常规划。

“会话摘要”仍是你预览确认的独立功能。“聊天回忆”仍供你查看原会话；“长期记忆”从正常聊天自动保存重要信息，不把每句话都记成事实。

## 费用与范围

优先支持现有官方DeepSeek结构化聊天路径，提取跟正常回复同次调用完成，最多4条。相关查询、置顶、停用和活动生命周期都不额外调用模型。提示与元数据仍占正常输入/输出Token，不等于零费用。其它服务若未开启同类结构化聊天，原文召回仍可用，自动提取可能没有条目；不强行改变现有模型配置。

长期条目最多16条、合计8KiB进入提示；历史原句最多4条、完整数据合计8KiB。使用现有jieba与SQLite FTS5/BM25按关键词检索，不是语义向量检索：明显的同义改写可能漏召回。没有后台扫描全历史或额外提取/embedding API。

记忆按世界、玩家、角色隔离。私聊来源只供对方角色；群聊公开原话只供该会话固定成员。不会把其他角色私聊、隐藏世界书或私人Observation记忆开放给玩家。用户已于2026-10-02明确授权上述有界历史原句随正常聊天发往所配置模型。

“关闭自动记录”停止该角色后续新条目写入，已有记忆仍可使用。停用的条目及其来源消息不参与新的长期档案召回；原聊天与近期上下文仍保留，所以这不是删除聊天内容。被明确更新的条目不能直接重新使用，以新记录为准。

## 活动开始、结束和中断

已接受的日常活动由Kernel开始并记录实际事件。世界时间达到活动结束点，既有世界调度器在一次事务内记录“活动时段结束”和相应亲历Observation，释放占用；活动到期不代表工作任务成功、拿到物品或达成约定。结束不会移动角色或玩家，不增加位置revision，以保持后续候选衔接。

角色被已有Kernel放置命令改变状态时，同一事务记录旧活动中断；新版启动后遇到旧版遗留的active候选也会核对状态。已终止的候选不会重复生成终止事件。关闭自动活动停止新规划和新活动，但已开始活动仍可自然结束；世界暂停时不推进到期，恢复后按世界时间处理。彻底退出时没有程序执行，重启也不补造未发生的活动。

聊天快照含当前活动对应的开始/结束/中断及最多6条本人已亲历的近期移动与活动，完整数据最多6KiB。通过主体ID、Observation权限和原事件过滤；角色卡习惯与他人台词不能替代实际经历，旧经历不能覆盖当前活动。玩家只看已获知的世界事件；后台活动不是全知时间线。

旧版已被标记finished而没有终止事件的历史不会被改写；此类记录只能说原定时段已过。普通用户目前没有手动中断活动按钮，也没有任务成果、物品系统或完整离线世界重建。

## 本版验证范围

按项目约定只做源码复核、静态检查、编译与包内文件核对，没有运行测试、应用、数据库迁移、GUI或真实模型调用。数据结构是新增0029迁移的两张应用记忆表，运行新版时沿用现有升级流程；不要用旧程序重新打开已升级的存档。模型是否自然、准确记住与使用信息仍由你体验验收。

更换程序目录后，自启动仍可能指向旧包。在设置中重新“保存并更新启动位置”；保留本完整目录及core子目录，无需再次解压。
