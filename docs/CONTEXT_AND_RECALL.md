# 上下文、记忆与长历史（桌面0.1.39）

更新日期：2026-10-07。本页说明当前源码；历史0.1.18～0.1.28的实现和检查不扩大为本版验收。详细改动见[长历史维护记录](maintenance/2026-10-07-long-history-recall.md)。

## 如何使用

1. 正常单聊或群聊。重要记忆仍与完整回复同次生成，最多4条，不增加提取/裁判API。历史原句只来自此角色参与过的当前世界、当前玩家会话。
2. 在角色回复下点击“本次参考内容”，查看当次检索方式、来源、容量和省略情况。记录是生成前准备的资料，实际模型用量以账单为准；旧消息可能没有记录。
3. 在“长期记忆”置顶重要身份、偏好和约定。明确更正生成新版本，旧条目停用或被替代后在检索前排除；原聊天和过去的参考记录保留。
4. 必要时在“会话摘要”手动生成、编辑并确认。不会逐句额外总结，不把未完成约定写成成果。
5. 主聊天页最多保留200条消息，点击“加载更早消息”继续上翻；“返回最新消息”回到最近一页。页面裁剪不删除存档。查看旧页时，最新轮询不混入旧页；已读仍仅按真实显示且可见的消息确认。发新消息时回到最新页。

## 持久全文索引与历史向量

Alembic源码head为0037_persistent_chat_recall，增加派生的recall_documents与FTS5表、同步触发器，不改写聊天、记忆状态或世界事件。新版首次启动沿既有迁移流程建空索引，不在启动时扫描/编码全部存档。本轮没有执行用户存档迁移。

正常聊天或明确搜索时，先按世界、玩家、角色、会话参与和记忆状态核验来源，再逐页补齐索引。每通道一页最多64条，优先较早尚无全文索引的记录；候选正文仍有数量/字节限制。jieba分词全文持久保存在FTS5；冷索引尚未覆盖的记录保留有界关键词候选回退，避免新索引建立前丢失原有关键词访问能力。已索引正文不再参与这条冷扫描。

历史语义查询不再只读取最近8192条引用。所有已索引且当前仍获准的向量都可参与，数据库按512条流式读取，逐页使用NumPy评分，每个问题只保留排名前16个，融合后最多取24个历史候选。每次历史扫描总等待最多3秒；超时保留已完成页的结果并标记部分召回。模型加载、候选新增编码也沿既有单工作者/超时回退，不堆积冷加载工作。迟到结果不插入已结束请求。

每次候选排序仍最多新增128个本地向量，正文编码取前2000字符，使用现有BGE-small-zh-v1.5。未索引历史和未编码长文本不能保证同义命中；本地索引逐步补齐不等于全部历史当次已搜索。冷启动CPU、超大历史耗时和召回质量仍待用户体验。运行时不下载模型，不向外部embedding服务发送历史，也不新增付费API。

## 缓存、权限与容量

完整历史向量现在另存于主SQLite的可重建派生表，不随256MiB DiskCache淘汰而失去索引。DiskCache仍在data/cache/chat-recall-v2，仅作为加速缓存；它容量有限，内存向量缓存也有上限。SQLite派生索引随历史量增长，会增加磁盘占用；每个向量负载2080字节，另有全文分词和数据库索引开销，没有额外加密。不要手工编辑运行中的数据库；本产品尚无一键重建索引界面。

索引不授予读取权限。每次全文/向量查询都重新连接当前源记录，检查来源版本与授权；保存派生页也在独立短事务重新核验。停用、纠正、跨世界/角色和不可访问会话不能凭旧索引重新进入提示。长期条目仍最多16条/8KiB，相关历史原句仍最多4条/8KiB；整尝试Token上限不变。

语义不可用时使用关键词，并在“本次参考内容”说明。持久派生写入失败不使合法回复失败，覆盖仍按部分召回处理；若主索引写入成功，DiskCache失败不再被误报为仅内存语义。

## 本轮待用户验收

- 使用早期旧事的关键词和同义表达，检查出处是否相关；首次冷索引不能承诺立即命中所有旧事。
- 更正或停用后，新回复不再参考被替代条目；跨世界/角色不能出现别人的私聊。
- 反复上翻长聊天、切回最新页和发送新消息，检查阅读位置、草稿、未读与流式回复。
- 退出重开后检查已索引来源仍可召回；请反馈参考面板的检索方式和表现，无需提供密钥或私聊全文。

本轮只做源码、lint/type、格式、文档链接及build-only编译/打包；未运行应用、数据库迁移、自动测试或模型推理。

## 仍保持的边界

近期完整上下文仍有界；本人近期活动最多6条/6KiB，获准亲历仍只在近128条中取近期8项与最多4项相关经历，最终12条/8KiB。本轮没有扩大Observation/EpisodicMemory权限或自动反思。当前真实活动、同次获准终态仍优先于旧开始，不补造成果。详见[经历召回](EXPERIENCE_RECALL.md)、[终态说明](EXPERIENCE_STATE_RECALL.md)。

Windows原生库仍在控制管道和后台线程前准备，模型本身按需加载；相关历史问题见[Core卡顿修复](CORE_NATIVE_STARTUP.md)。聊天/读取失败的恢复边界见[生成与读取修复](GENERATION_READ_RECOVERY.md)。
