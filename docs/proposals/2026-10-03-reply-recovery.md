# 已批准的失败回复恢复方案

2026-10-03，源码基线 D:\LivingWorld / 8303d32。用户明确选择“采用独立新尝试，点击时明确费用”，已由 [AGENTS第25节](../../AGENTS.md)记录，覆盖第23节针对原消息额度的这一处例外。

1. 仅针对会话最后一条玩家消息，且其后没有任何已保存角色发言。已完成回复不替换，部分群聊暂不补续。
2. 尚未领取的 pending 回合手动使用原生成入口和原保存额度，不创建重复消息或新额度。
3. 新版记录的、已结束的本地回复校验失败，或Core启动前可靠标记的本地中断，可以显式创建新的付费尝试。界面确认当前聊天额度；原回合、原用量及未知费用预留均保留，仍受已有模型费用治理。
4. 新尝试有独立一次领取、来源关联、当前额度和幂等准备回执。准备丢响应仅可重复同一个请求；准备回执不等于已调用模型。实际生成复用原私聊/群聊预算、流式、验证和落库路径。
5. running或unknown只查状态，不允许重放。旧版本已领取却没有结束记录的回合归unknown；网络断开、取消或结算异常不能由前端自行认定失败。启动只把新版仍running的本地任务标为interrupted，不调用模型、不清空原用量；已经unknown的回合保持unknown。
6. 同一尝试内部的选人、路由重试、回退和所有发言者继续共享它自己的上限。本方案不是后台自动付费重试。

实现新增0031的两个应用表：执行状态与恢复来源关联。原ChatMessage不复制或修改，历史原句与事件/记忆来源仍指向真实消息。创建事务核对当前绑定玩家和最新尝试；领取前再检查源消息仍是最后一条。详情见[功能体验说明](../CHAT_FUNCTIONAL_EXPERIENCE.md)。
