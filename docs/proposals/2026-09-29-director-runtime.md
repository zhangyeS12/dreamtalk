# Director 初版运行方案（已获用户批准）

2026-09-29，基于 bd50a3c；上一轮用户报告体验无问题。用户已明确批准“一次开启后自动运行（推荐）”。以下推荐规则成为本轮实现依据；实现进度以 HANDOFF 和代码为准。

## 推荐的用户体验

用户在当前世界设置中首次开启“世界自动活动”，看到采用哪个模型、后台规划会产生用量、可以随时关闭，并确认授权。之后角色根据批量计划生活；玩家只看到自己获知的变化，不每隔几分钟审批活动，也不接收后台全知剧情。角色台词仍由对应角色生成。

角色卡、世界书和会话摘要的创作流程仍逐次 Draft → Preview → Commit。建议将运行时 WorldPlan 明确归为在用户已授权范围内执行的运行计划，不要求每一批人工预览确认；这一分类正是 P-16 尚未明确的边界。备选方案是每批计划经用户确认才进入候选池，等待确认时世界活动不续批。

## 建议一起确认的业务规则

| 决策 | 推荐默认规则 | 对用户的影响 |
| --- | --- | --- |
| 启用范围 | 每世界独立、默认关闭；启用时确认后台模型用量，关闭阻止新规划及未执行候选 | 现有存档升级不会自行开始付费或自动活动 |
| 批量确认 | 一次开启授权后，后续合规运行计划自动进入候选池；创作内容仍逐次确认 | 保持“角色在生活”的连续体验；关闭可停止后续工作 |
| Planning Window（P-05） | 一批覆盖6小时 WorldTime，窗口未结束不因小偏差重规划；普通聊天/Busy不改变世界时钟 | 不是每6小时盲抽事件，也不是按现实分钟轮询模型 |
| 耗尽 | 世界逻辑时间到达该批 window_end 才算时间窗口耗尽；候选提前完成不自行触发额外规划 | 不靠重复调用模型填充空白 |
| 大量失效（P-05） | 同一计划中，因角色/地点/必要状态假设改变而不能执行的候选，达到原批总数的50%，且至少2条，才允许提前重新规划 | 少数偏差只取消对应候选，不逐条请求模型；可配置值后续在高级设置公开 |
| 费用范围 | 沿用当前已配置模型及原金额/Token治理；每批独立有界任务，输出上限8192 Token并取模型更低限制；下一批是新的计费任务 | 所有提供商一致，不特殊绑定 DeepSeek；后台授权与额度必须明确 |
| 失败/空计划 | 已dispatch失败或中断不自动重放；空/无可执行候选的输出视作不可用，进入需处理状态，不自动循环生成 | 避免重复费用；用户可查看安全状态并显式重试新任务 |
| 权限（P-17） | Director仅能提案当前世界已有、已放置Character的日常活动与移动；新typed action逐项经Kernel校验 | 不伪装 CHARACTER_RUNTIME，不移动Player，不直接改关系/知识/台词 |
| 冲突 | 同一角色在同一世界时间只执行一个活动；CAS或前提冲突取消候选、记录原因；没有静默改目标、无限延期或重新调用模型 | 行为可解释、恢复不重复事件 |
| 衔接 | 新计划原子替换旧批尚未执行候选；已提交WorldEvent/已发消息保留；已经开始的活动先结束，不被新批瞬间改写 | 不覆盖真实历史，也不同时运行两套互相冲突的未来计划 |
| 世界关闭/暂停 | PAUSED不消费计划；应用关闭不运行后台AI；返回时只消费有效旧批，到其有效窗口为止，再按授权条件续批 | 超过旧窗口的长离线不会伪造多天的未规划生活 |

6小时/50%/至少2条是建议值，当前文档明确没有默认值，批准后按该数值实现生产策略。输入、角色和候选数量等工程界限在实现时保持有限，并明确显示容量不足；不以静默截断替代完整计划。后台单次调用服从原账户金额预算，不在本提案里擅自设置价格或自动加额。

## 分批实现

1. **批量规划与状态**：新增受控 Director operation、World 独立开关、持久单次claim、typed WorldPlan/Candidate、当前世界只读安全状态；首先实现明确授权后的生成/校验，不冒称已有活动消费者。
2. **角色日常执行**：添加角色活动/move typed Kernel action、候选到期消费与幂等结果。复用当前 Movement、Scene离开、scheduler、WorldTime、Observation。导演不直接写 projection/event。
3. **自然获知与主动联系**：基于角色已获知的真实事件生成统一目的的 Outreach；先单角色，再多人。Busy不发普通主动消息，同理由一次。P-03/P-04 的理由等价与 Episode 规则在这一阶段另行给出可审阅方案，未定义前不发送。

第1步不会把候选描述当作发生的事实。第2步的执行入口才使真实角色活动进入世界；第3步才产生无人先发消息时的主动联系。每步均交付独立可体验包，不能合并宣称完整 Director 完成。

## Kernel 与隐私的技术边界

- Director 从可信组合处获得同世界必要的物理状态、已接受角色资料与明确开放背景，不读 Character 的私有聊天、记忆和信念，也不读取未开放世界书暗线。
- 模型只选择已提供的 Character/Location ID和注册动作，不创建脚本/SQL/地点或任意世界影响；候选不能为自己选择观众或授予知识。
- DIRECTOR → Character日常动作是新增显式权限，不借用系统/角色身份绕过原禁止规则。Player movement仍只接受本人 PLAYER_INPUT。当前 ACTION_RESOLUTION 的权限表需要记录批准后的扩展。
- Kernel提交实际状态/WorldEvent，按发生时真实观众创建Observation；离线/不在场玩家不自动见证。现有世界事件/角色自己的事件上下文继续独立授权。
- 每个候选有稳定身份和action receipt；候选状态、真实结果与重试遵循同一事务或可从已提交receipt确定恢复，不重新派发有费用任务。重开界面只读状态。
- 关闭自动活动时阻止新dispatch；已经在提供商执行的请求可能仍产生费用，迟到结果不得重新启用世界活动。不能承诺关闭即退款。
- 普通设置显示启用状态、模型费用说明、是否需要处理；不显示隐藏候选、其他角色地点、关系数值或完整规划输入。授权预览不能变成全知监视面板。

## 为什么要确认这一轮

[AGENTS.md](../../AGENTS.md) §14/18/22要求未定产品、权限及费用规则不被默认实现；[DIRECTOR_MODEL.md](../architecture/DIRECTOR_MODEL.md) §3.2明确没有“耗尽/大量失效”的阈值，运行时计划确认边界未定；[ACTION_RESOLUTION.md](../architecture/ACTION_RESOLUTION.md) §3目前不授予 Director 角色行动权限。本提案不改变 Kernel/知识/聊天规则，只将这些依赖列成一次可审阅产品选择。

测试与运行验收仍由用户负责；工程端继续只进行源码/lint/type/编译打包。上一轮验收没有列出分项，不扩大解释为全产品、所有权限隔离或完整世界活动已验证。
