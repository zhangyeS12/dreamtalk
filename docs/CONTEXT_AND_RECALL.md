# 上下文与记忆体验（桌面0.1.22）

请退出旧程序，保留存档并启动完整的新便携目录；不要只替换EXE。新Core与本地中文模型在core子目录，第一次启动按既有Alembic流程升级新增可空诊断列。

## 如何使用

1. 单聊或群聊正常发消息。记忆提取仍与回复同次生成，不增加额外API；历史原句只从此角色参与过的会话选取。
2. 角色回复下面点击“本次参考内容”，查看本轮各角色的检索方式、预留额度、候选省略情况和长期记忆/历史原句来源。旧版本消息可没有记录。记录是生成前准备的资料，实际模型用量以账单为准。
3. 在“长期记忆”置顶重要偏好、身份或约定；更正/遗忘后，未来检索不再使用旧条目。历史参考记录保留当时的来源，不修改已发送消息。
4. 会话特别长时在“会话摘要”手动生成并确认，复用旧摘要合并新增原文；不会每条消息额外总结。旧约定无履行证据不会被写成已完成。

本地BGE编码最近一批授权候选，再与关键词/BM25排名融合。它处理同义表达，不能保证所有很久以前的原句都被搜到；关键事项建议置顶或摘要。模型首次载入和冷缓存会额外使用CPU，每次最多新增128个候选向量，其余随后续聊天/搜索逐步缓存；面板会说明部分缓存状态，实际耗时待体验。模型缺失或不兼容会回退关键词并在参考面板说明；运行时不下载模型。

## 本次待验收

- 多聊几轮后用同义表达询问已说过的偏好，检查引用原句是否相关；跨角色/世界不得出现别人的私聊。
- 将“喜欢咖啡”明确更正为“不喝咖啡”，观察新回复是否遵循更正；旧约定、休息记录不能覆盖当前活动。
- 大量背景、长单聊和多角色群聊时，当前问题及当前轮发言保留；省略条目有可查记录。
- 完整包中参考面板应显示“关键词＋本地中文语义检索”；若回退，请反馈此提示与现象，不必提供API密钥。

编译/静态检查不等于上述行为已验收。本轮未运行应用、自动测试或模型调用。

## 长历史与重启（0.1.20）

聊天与手动记忆搜索会在本地逐步建立较早历史的向量索引，已编码结果重启后可以复用。每通道最多检查8192条当前获准来源的ID，只取命中正文及最多64条未编码历史；每次新增编码仍最多128条。不会自动批量联系模型，也不会把全部历史加入提示。首次用到模型仍需要CPU载入，磁盘缓存不能省去这一步。

缓存位于应用数据的data/cache/chat-recall-v2，目标容量256MiB，仅保存摘要/向量，不保存第二份聊天正文。向量属于用户数据，文件没有额外加密。角色权限、遗忘和更正始终由原存档决定；缓存失败时使用内存，面板会说明，下一次程序启动再尝试磁盘缓存。清理缓存只影响后续重新编码，不会删除聊天或记忆，但不要在程序运行时操作文件。

体验重点：先在记忆中搜索旧经历，再换一种说法检索；退出重开后查看来源是否仍能取回；遗忘或更正后检查旧内容不再进入新回复。冷缓存会显示“较早历史正在逐步建立本地索引”；未建立的同义内容未必当次被搜到，重要信息仍可置顶。大规模历史耗时与召回质量尚未实测。

## 读取与冷启动（0.1.22）

每次本地语义工作等待最多3秒；繁忙、超时或不可用时继续关键词检索，不让该步骤无限等待。真实工作完成后可供后续请求复用，但迟到的结果不会插入已经结束的请求。同一时刻仅一个工作，不堆积并发冷加载。近期聊天、置顶记忆、摘要、历史条数/字节上限和权限过滤不变；不删除旧记忆，不增加付费API。原生线程不会因超时被强制终止。

本地GET最长等待15秒，失败后可重新读取。模型状态正在读取、读取失败和确实不可用分别提示；“刷新记录”同时重新核对模型状态，只读不生成。实际聊天与冷缓存体验仍待验收，见[生成与读取修复](GENERATION_READ_RECOVERY.md)。
