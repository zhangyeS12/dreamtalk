# 角色相遇与经历召回（桌面0.1.26）

角色可以把真正短暂碰面的经历带进之后的聊天。例如铃和艾莲都在咖啡馆休息，日常计划安排问候；到时双方仍在场且活动有效，才记录碰面。仅同地点、未来计划或一句聊天设想不会自动产生共同经历。0.1.26减慢新增见面对象的速度，避免持续同场重复记普通问候。

## 如何开启

1. 从旧托盘选择“退出并停止后台运行”，打开完整encounter-pacing/dreamtalk目录里的dreamtalk-desktop.exe，保留core目录。在“设置 → 后台运行”核对0.1.26；需要自启动时，在新版显式“保存并更新启动位置”。本机生成的完整目录可直接运行，无需再解压。
2. 通讯录打开至少两名角色的私聊，在设置给角色指定初始地点，准备合适的活动地点。
3. 在“世界自动活动”开启已有日常规划，再在下方“角色相遇”允许角色相遇，首次确认同批后台用量。
4. 开启等下一批正常六小时规划，不因保存立即调用API；刷新也不调用。正常后台批次仍按原授权自动运行。模型可以返回0次相遇，不保证每批碰面。暂停时不执行活动；错过的碰面不会补演。
5. 之后正常问角色“最近遇到谁了？”或提到对方。回答只依据本人已有观察；近期与较早相关经历可一起召回，仍在近128条词法候选、最终最多12条/8KiB内。不额外调用API判断记忆。

## 相遇节奏

- 每个已接受计划最多成功2次普通问候，模型可提0、1或2次。两人必须同地点、真实处于对应的休息或自由活动，不能打断工作。早期重新规划得到另一批；这不是全世界滚动六小时总额度。
- 每个角色滚动24小时**世界时间**最多新增一位首次实际记录的见面对象。A已经首次见过B，则这24小时不能再安排A首次问候C；B也受同一规则。曾经成功问候过的对象重逢不花新增对象额度，仍受其他限制。不保证24小时一定新增对象，也不把背景里的既有朋友改成陌生人。
- 同一对在连续同一地点的停留期间，只记录一次普通问候。换一段休息/自由活动、revision变化、重启或关闭再开启不算离开。一方确实离开再返回，才可以再次考虑；同一对还需距上次成功碰面至少6小时世界时间。原最多5分钟有效窗口和双方活动结束边界保持。
- 旧0.1.25计划可能含较多候选，新Kernel也会限制执行数。已经发生的旧事实保留并参与冷却/新增对象判断，不追溯删除。额度或同场条件不满足时只取消该候选，不补选、不触发额外付费重规划，不影响正常日常。
- 去重针对普通问候。工作、休息、移动等真实活动变更仍正常记录，不会把有意义的新经历一并删除。

## 见过不等于熟悉

相遇只记录短暂打招呼，不证明双方交换姓名、正式介绍、私下谈话、共同完成任务或成为朋友。聊天资料明确标记brief_greeting、relationship_effect=none；参与者与目击者仍区分。模型应按各自来源区分“见过、打过招呼、正式介绍、共同经历”，不能因几次普通问候自动升级关系。已有独立授权背景里的亲缘/熟识保留。

本版没有新增正式介绍或共同委托动作，没有自动关系推进；这些需要各自明确的事实和执行结果。提示约束也不是自然语言语义裁判，模型具体表达仍需体验核对。

## 可见范围、费用与数据

双方各自保留见闻，实际在场且获准的其他主体可以目击。群聊成员不自动知道后台碰面；玩家不在场时不会直接收到全知世界事件。角色自然聊天说起时，沿已有聊天获知路径整理，既有提取规则决定是否成为条目。开启不增加其他角色私聊、私人记忆或隐藏世界书输入。

每次碰面、限额和同场判断都不调用模型；同原日常共用一次规划。正常规划与聊天仍按实际输入/输出产生用量，遵循原独立后台预算。关闭取消待执行候选、保留已发生见闻；关闭Director或退出应用停止后续执行，迟到规划不恢复已关闭功能。相遇取消不计入日常半批失效的提前重规划门槛。

沿用0033两张相遇表及CharactersMet v1，不增加迁移、不回填历史、不改幂等UUID。Kernel同一写事务复核授权、真实位置/活动、时段、节奏，并原子提交事实、获准观察、候选结果与ResolveEncounter回执；重复领取返回已有结果。新节奏是准入规则，旧合法事实仍按原v1契约重放。

本轮只做源码审查、lint/format/type、编译及包内静态字节核对，没有自动测试、桌面/Core/模型或真实存档诊断。待用户体验：持续同场是否仅一次问候、离开返回仍遵循冷却、每角色新增对象是否受限、旧问候不升级熟悉、切世界/重启后记录是否保持。没有碰面本身不等于失败。

复用与具体规则见[成熟方案调查](research/2026-10-04-encounter-pacing-reuse.md)。最初[0.1.25批准方案](proposals/2026-10-03-character-encounters.md)的8次上限已由本次用户接受的2次规则替代；[经历召回](EXPERIENCE_RECALL.md)范围保持。

## 桌面0.1.27共同休闲

用户另行批准已实际碰面角色的共同休闲生命周期，独立默认关闭，不覆盖短暂问候。普通问候与共同开始合计每批至多2次，原新增对象与持续同场去重保持。详见[具体体验与边界](SHARED_LEISURE.md)。
