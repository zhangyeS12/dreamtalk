# 在聊天中回忆角色亲历

本页描述当前已实现的亲历召回；版本、发行和用户验收见[状态清单](PROJECT_STATUS.md)。它与[长期聊天记忆](LONG_TERM_MEMORY.md)及聊天历史的本地语义检索不同，不把角色说过的话直接当作真实经历。

## 来源与范围

在私聊或群聊问角色过去的地点、活动或相遇时，系统按当前问题和前两句，从该发言角色自己获准的观察中检索。保留近期资料，在近128条授权资料中做词法排名，最多补4项相关旧经历；最终最多12项／8KiB。当前本人活动另有快照，不因较早经历命中而覆盖现在。

只读取同世界、绑定角色已获准的真实事件。没有对应观察或查不到时不能确认发生过；检索窗口有限，也不保证同义说法或更远历史命中，不额外调用模型判断经历。后台记录不会直接变成玩家事件页里的全知时间线。

## 已实现的相遇与共同休闲

[角色相遇](CHARACTER_ENCOUNTERS.md)和[共同休闲](SHARED_LEISURE.md)均已有实现，分别按授权和 Kernel 条件执行，不再属于“待实现相遇”。仅已提交事件进入双方或获准在场者的观察检索。

CharactersMet 投影区分参与双方、旁观者和 `brief_greeting`，普通问候的 `relationship_effect=none` 不证明交换姓名、私聊内容、正式介绍或关系提升。既有独立授权的亲缘／熟识背景仍可使用。共同休闲只证明真实开始、结束或中断，不自动生成工作成果或关系进展。

同一次活动的开始与唯一获准终态按稳定开始事件 ID 组成检索组，搜索两阶段文本，优先返回实际后续状态，避免重复占名额；缺少、冲突或无权读取的终态不猜测。详见[后续状态召回](EXPERIENCE_STATE_RECALL.md)。

## 接手位置与核对场景

源码入口为 `services/core/src/livingworld/infrastructure/persistence/player_event_feed.py` 及同目录事件投影／观察召回模块；本人近况另见 `application/character_activity_context.py` 和对应持久化 reader。问具体旧经历，再追问“现在呢”，应分别沿历史证据和当前本人状态回答；还需按不同角色／世界及当事／旁观范围核对，实际模型表现见状态清单。

安装和本机入口统一见[开发说明](DEVELOPMENT.md)与[安装手册](PORTABLE_WINDOWS.md)，不使用旧体验包目录或旧版本号判断当前能力。
