# 共同休闲与来源回看（桌面0.1.27）

## 如何体验共同休闲

先从旧托盘“退出并停止后台运行”，直接运行完整 shared-leisure/dreamtalk 目录中的 dreamtalk-desktop.exe，保留 core/。本机已生成完整目录，无需再解压 ZIP；在“设置 → 后台运行”核对0.1.27，需要自启动时在新版明确保存更新启动位置。

在“设置 → 世界自动活动”依次开启自动活动、角色相遇和新的“共同休闲”。三个许可分别保存；共同休闲默认关闭，首次说明同批后台用量。保存不立即调用模型，下一正常六小时批次才参与。角色需有已有的成功短暂碰面记录，且之后同地点、同类型的实际休息/自由活动重叠至少15分钟。

一次提案时长15～30分钟世界时间；普通问候与共同休闲合计每批至多两次，同角色每滚动24小时至多开始一次共同休闲，同一对至少6小时冷却。0条有效，不为了展示效果凑活动。不因取消候选额外调用API或按社交候选触发日常半批重规划。

Kernel在真实执行时记录开始；双方保持原活动/地点且完整时长过去，才在结束后五分钟内记录正常结束。离开、换日常、撤销授权、计划更换会中断；暂停冻结世界时间。重开时旧active活动的连续执行不可确认，记录中断，不补造共同完成。每个候选最多一次开始和一次互斥终态，事件、观察、候选和幂等回执在一个写事务内保存。

随后可在正常私聊/群聊中问当事角色“你最近和谁一起待过一会儿？”聊天只参考发言者有权限的亲历，区分参与、目击、开始、结束和中断。未亲历的玩家不会直接收到后台活动清单，仍通过正常聊天获知；远程群成员不自动在场。开始不等于结束，结束不代表谈了什么、买到物品、委托胜利、正式介绍或关系进展。

该功能复用现有Director同一次调用和Kernel调度，不逐活动调用模型，不新增相遇历史或私人资料外发。不保证某批必有合格共同活动；已有相遇冷却及当地有效日常仍会拒绝不合格提案。

## 回看记忆和事件的来源

聊天顶部“长期记忆 → 查看来源 → 查看原文前后文”，或“世界事件 → 聊天获知 → 来源原话 → 查看原文前后文”。只读原会话中那条稳定ID消息和前后各最多3条，高亮来源消息，显示原消息时间；离线消息保留“时间详情”中的实际生成时间。不是按原句猜测匹配或读取全部历史。

跨会话长期记忆回看使用条目自己的来源会话；当前世界/身份必须拥有该原会话。角色名按已知主体ID匹配，未知群成员显示“其他角色”，不把他人台词全算成记忆所属角色。原消息不可访问时仍保留此前保存的原句，可明确重试读取；关闭、切换条目或世界会取消旧请求、忽略迟到结果，不发送消息、不改变已写批注或记忆状态、不调用模型。

来源窗口关闭后可继续置顶/停用记忆或编辑事件批注。看到原话仍不证明内容为世界真相。相关设计复用[Zulip稳定消息链接的回看方式和现有组件](research/2026-10-04-shared-experience-reuse.md)，没有新聊天框架或依赖。

## 数据与验证边界

0034只新增共同休闲许可和候选两张表；保持0033及旧事实、UUID、回执，不回填旧共同经历。旧结构检查明确识别0033，不能误按0034完整形状拒绝旧存档。启动升级由用户体验；没有替用户读取/修改存档，也不要再用只支持0033的旧包打开升级后的存档。

本版只做源码、lint/type、AST/结构声明与文档核对、编译和包字节核对。没有自动测试、Core/GUI启动、数据库升级诊断、模型推理或付费API；构建成功不代表运行验收。重点体验来源定位/ESC返回/批注保留、权限边界、共同开始/结束/中断、暂停/重启和频率限制。


## 0.1.28聊天中的后续状态

同次共同休闲已有该角色获准的结束/中断时，历史检索优先后续状态，避免较早开始单独占名额或被误当成仍在同行。仅目击开始不能得到隐藏结束，完整原始历史保留。见[经历状态召回](EXPERIENCE_STATE_RECALL.md)。

## 0.1.32 阵营相识

用户明确加入同一个阵营的直接成员已有相识，不再要求先执行一次碰面；父子阵营不继承这项相识。实际同地点/日常、许可、冷却和生命周期仍逐项核验；已有熟人仍可有新见闻和同目的共同邀请。见[阵营说明](CHARACTER_FACTIONS.md)。
