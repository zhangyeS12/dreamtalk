# 阵营、人物头像与关系网（桌面 0.1.32）

进入当前世界 → 通讯录。新建角色卡和导入入口仍在原位置。

## 设置阵营

在“编辑阵营”输入名称，父阵营留空创建顶层阵营；选择父阵营即可建立子阵营，没有层级数量限制。选择当前角色，勾选对应阵营；同一角色可以加入多个阵营。页面显示每个阵营的直接成员；修改可重命名或换父阵营，禁止循环；只有无直接成员、无子阵营的空阵营可以删除。

例如将艾莲、莱卡恩、丽娜直接加入“维多利亚家政”，三人立即相识。若将两人只加入其子阵营，他们彼此认识，但不会据此认识父阵营的其他成员。归属没有传递性：A认识B、B认识C不意味着A认识C。

退出阵营只改变当前归属，保留已经建立的相识；更新同一角色卡继续使用稳定根身份，归属和头像不会随卡片修订丢失。文件导入新的角色卡仍是另一个角色，不按同名合并。

## 头像与关系网

选择“角色资料”上传 JPG/PNG/WebP 静态图片，最大 10 MiB；建议方形 512×512 或 1024×1024、人物面部放在中央。沿已有图片服务验证尺寸、EXIF、解码及本地存储；圆形展示使用中央裁切。可移除头像恢复名字首字，图片不会发送给模型。当前头像展示范围是通讯录与关系网。

“人物关系网”显示当前世界所有已确认角色及有明确阵营相识依据的联系；不从隐藏知识、亲密度分数或一次短暂问候推断正式相识。拖动空白处移动、滚轮缩放；点击头像或用键盘激活会迅速居中，右侧显示全名、完整阵营路径和“打开会话”。没有绑定玩家身份时先进入世界才能开聊。首次布局按连接分组，图上位置不代表世界中的真实地点。

## 聊天、活动与费用

下一次正常聊天会提供发言角色本人所属阵营和已确认熟人：至多8个阵营、每阵营16名同伴、24名相识，合计4 KiB；按容量可省略，不能据此编造共同秘密、往事或亲密度。现有“本次参考内容”显示该类资料是否保留。

共同休闲不用再等待同阵营伙伴先碰面，但仍须开启相应活动许可，双方实际处于同一地点、兼容休息/自由活动，并满足冷却、日常计划和Kernel核验。已有相识仍可产生实际碰面/共同活动见闻。共同邀请仍须同一件真实共同活动、同一目的；未回复上次主动联系时不会新发联系。设置阵营、头像或刷新关系网不会调用模型；有界新上下文参与之后原有聊天/规划请求的正常输入用量。

## 验收边界

新增0036四张表：阵营、直接成员、头像绑定、持久相识；保留旧消息、事件和数值关系，不运行真实存档升级或模型诊断。此前的0035旧包不应打开用户自行启动新版后已升级的存档。

本轮仅执行源码、lint/type/format、文档与 build-only 检查；以下由用户体验：多重归属、父子隔离、重复加入不重复连线、退出后保留相识、头像上传/移除/重启、卡片更新保留、拖动缩放/键盘聚焦/聊天跳转，以及模型对熟人自然称呼与共同联系条件。构建成功不代表这些运行场景已通过。

实现复用[React Flow](https://reactflow.dev/)，选择理由、当前版本和许可见[批准方案](proposals/2026-10-04-character-factions.md)及[许可清单](licenses/relationship-network/README.md)。
