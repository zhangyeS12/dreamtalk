# 架构决策记录（ADR）

ADR 用于记录具体架构问题的背景、证据、备选方案、取舍和确认结果。本文是记录规范，不是一项技术选型 ADR。

已接受：[ADR-0001：优先评估成熟项目复用](0001_reuse_mature_projects.md)。

## 使用方式

- 文件命名：`NNNN-short-topic.md`，例如第一份记录使用 `0001` 编号；名称示例不表示决策已经存在。
- 区分“提议中”“已接受”“已否决”“已替代”的状态；未经确认的提议不能标为已接受。
- 涉及冻结产品规则时，引用 [PRODUCT_SPEC.md](../../product/PRODUCT_SPEC.md) 对应 FR 编号。ADR 不能自行修改冻结规则；冲突应交回产品定义澄清。
- 后续改变已接受决策时，保留原记录，新增替代记录并相互链接，保留决策历史。
- 调研材料保存在 [research](../../research/README.md)，ADR 链接具体证据，不用尚未验证的推测冒充调研结论。

## 每份记录应包含

1. 标题、状态、日期与确认记录。
2. 背景、待解决问题和涉及的冻结规则。
3. 约束、评估标准与仍未确认的产品前提。
4. 备选方案及来源、验证方式和结果。
5. 决策与理由；提议阶段明确写出“尚未决定”。
6. 影响、代价、风险与需要重新评估的条件。
7. 关联文档以及被替代或替代本记录的 ADR。

原 Stage 0 基线没有预选 Web 框架、前端框架、数据库、Agent 框架或部署方案；后续决策以各阶段接受的记录为准。
