# 已批准：五个存档位置

日期：2026-10-17。用户确认行为后明确允许开始修改。本决定替代旧方案中普通用户的30分钟历史备份、无限手动列表及清空入口；更新和迁移保护继续独立治理。

- 书架“检查更新”旁为“存档”，提供一个自动位置、四个手动位置；用户指定专用文件夹。
- 每次启动在当前数据、更新及书架就绪后保存一次自动档，覆盖上次自动档；刷新界面、切换世界、Core设置重启不重复触发。首次指定位置后补做本次尚未完成的自动档。
- 当前全部世界、角色卡、世界书、身份、记忆、聊天及关联素材整体保存。普通操作继续即时持久化，不改变应用标识或当前数据位置。
- 位置有可编辑名称和右下角保存时间。手动位置可保存当前数据、按文件或完整路径导入、替换及导出；自动档可另存到指定手动位置，复制的是自动档本身。
- 导入只登记展示，不加载。目录清单按顺序最多读取五条及其文件，忽略后续位置，不删除未使用的旧文件。
- 每次打开页面提醒：加载手动档立即切换全部世界数据并覆盖自动档；要保留原自动档，应事先另存到手动位置。加载另作明确确认。
- 加载排空已有任务并正常停止Core，在临时副本检查结构和迁移；保留原数据，先校验新数据再提交自动档清单。失败或中断按日志完成或回滚，启动先收尾再开放业务。
- 本机API配置、密钥和模型程序路径不被他人存档替换；费用和调用保护沿当前机器保留，旧生成不重发，后台生成开关需重新开启。
- 不向普通用户暴露清空原始数据入口，卸载继续保留数据。旧`.dreamsave`可显式导入手动位置，更新保护材料不占用四个手动位置。
- 本轮授权实现和必要编译；用户另明确允许本轮隔离检查，仅使用仓库外临时合成数据和对应界面，核对五位置、导入、另存、加载和中断回滚。不访问真实存档、系统凭据，不调用外部模型或产生费用，不运行已安装应用／安装器，不打包或发布；用户随后另明确批准提交并推送当前源码，见[同步记录](../maintenance/2026-10-17-source-sync.md)。

复用现有SQLite Backup API、文件摘要、恢复日志及Python标准库ZIP，不增加依赖或第二迁移authority。本机检查环境Python3.13.7、SQLite3.50.4；发布环境仍以对应构建为准。参考[SQLite在线备份](https://www.sqlite.org/backup.html)、[封存文件immutable语义](https://www.sqlite.org/uri.html)、[Python ZIP边界](https://docs.python.org/3/library/zipfile.html)。SQLite为公有领域，标准库沿Python许可。未采用外部存档框架或复制其源码；现有组件已覆盖一致性快照与封存，额外框架会增加格式与恢复维护成本。目录清单和五个位置属于本项目有限编排。
