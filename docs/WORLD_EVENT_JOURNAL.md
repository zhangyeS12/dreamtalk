# dreamtalk：聊天获知与世界动态

桌面0.1.5把聊天列表顶部的“世界事件”分为两块。事件是有时间和来源的信息；旧记录不代表角色现在仍在做同一件事。

## 聊天获知

桌面0.1.9在官方 DeepSeek Chat Completions 普通聊天中使用明确JSON格式提示与本地校验（省略服务端response_format），角色在正常私聊或群聊回复的同一次调用中附带最多3条事件候选。具体活动、未来计划、传闻、邀请和计划变化才应记录，寒暄、心情、习惯、假设和重复闲聊可以不记录。没有另外调用模型分类，但提示、历史记录和元数据会增加少量有界 Token 用量，仍按正常聊天预算计费。

例如“我明天下午想去商店购物”可以记录为计划，而不是已经购物。列表保留角色、原话、获知的现实时间、获知时的世界时间，以及原话中的事件时间；没有明确时间就显示未明确，不把“明天”猜成某个现实日期。以后明确改变同一计划，可以关联旧记录；旧原话仍保留。批注／纠正不会改写原聊天，移除只隐藏该条事件记录。

本轮优先支持官方 api.deepseek.com 的受支持配置；不会替换你配置的模型。其他服务保持原聊天能力，自动事件提取待分别适配。旧聊天不付费补录，离线联系消息暂不自动提取。完整普通台词也可以成功保存，该次不产生新的事件或长期记忆条目，不额外调用API补提取。完整JSON代码块可按同一规则解析。元数据校验失败时可忽略该条记录，不发起额外付费修复；空正文、截断或损坏的JSON仍走回复错误流程，不把内部字段直接显示为台词。

原句必须真的出现在回复里，来源和旧记录引用按当前世界、玩家、发言角色及会话核对。去重采用有限来源／原句指纹，不额外调用语义裁判。模型仍可能漏记、误归类或说错事实，用户可批注和移除；元数据的本地校验不等于语义事实核实。

“我亲历的活动记录”折叠区域保留原来按玩家观察授权的记录；角色另外读取自己的亲历资料。聊天自述不是世界事实，也不新增角色记忆、观察授权、物品或关系。

## 世界动态

先在当前世界确认世界书，并逐条设为“公共背景”。打开“设置 → 世界动态事件池”，首次开启确认后台模型用量授权。该功能每世界默认关闭；与角色自动活动、离线联系分别开启。只发送已公开背景标题、正文、世界名称和已有动态标题，不发送私聊正文、隐藏世界书或私人记忆。

每次生成10条动态存入隐藏事件池，首条就绪后发布，其余按有效世界时间随机逐条发布，通常间隔15～45分钟世界时间。不是一次把整批展示出来；模型只在生成整批时调用。候选可用时间在本批前6小时内，过期窗口在12～24小时世界时间内。0.1.22允许模型省略窗口，由系统默认立即可用、24小时过期；提供的窗口仍严格校验。真正发布时记录当前世界时间和现实生成时间，不补造错过的历史公告。

每条右侧由你操作：红色“未经历”、绿色“已经历”、灰色“跳过”，同时有文字和键盘按钮。模型不判断你是否经历。达到最近整批10条的80%（8条已经历或跳过）时自动生成下一批，每批仅触发一次。旧的未处理动态继续保留，未处理总量有100条上限；取消或过期候选不会被当作已经历。

如果池已无可发布候选，但仍未达到8／10，可以在设置显式点击“生成新一批（调用模型）”；出现中断、背景变动或模型错误时也在这里处理。刷新事件／刷新状态只读取，不调用模型。批量生成输出不合规时不会自动花钱修复或重发。

程序及Core运行、世界未暂停时才会发布。关机后不生成，恢复时不把错过的公告全补出来；未过期候选继续，过期候选取消。世界暂停不推进发布。此功能与Director的6小时活动批次及50%失效重规划分别治理，但模型调用复用当前既有路由和财务预算。

动态可以是活动预告、公共通告、传闻或探索邀请。Kernel记录的是“这条公共消息已发布”，不证明传闻真实、活动已完成或玩家已参与；绿色标记也不改变物理世界。可以点“聊聊这件事”选择已有会话，核对草稿后手动发送。

## 更新和验收

退出旧程序应使用托盘“退出并停止后台运行”，再打开完整0.1.6目录。首次启动沿用现有升级机制增加0028的五张应用数据表；不要随后用不认识新schema的旧程序打开同一存档。更新前保留自己的存档备份。换目录后如需自启动新版，在后台设置点击“保存并更新启动位置”。

运行验收仍由用户负责，源码／静态检查、编译及包内字节核对不代替验收。0.1.6修复按用户授权只读查询了限定错误元数据，未修改存档、执行测试、启动应用或调用真实API。用户验收重点：普通私聊／群聊具体计划有原句及时间，寒暄不应大量记录，变更保留旧记录，批注／移除保存；公共动态逐条出现、颜色手动切换、8／10才续批、暂停／重启后不重复发布或调用，以及世界／玩家／角色隔离。

## 0.1.6 故障修复

“生成失败”现区分格式不合规、空回复和输出截断；不会据此自动增加额度、重发消息或新增模型调用。同次提取的格式规则放在角色规则之后。官方DeepSeek Flash／V4 Pro两类小JSON任务显式不启用thinking，原预算和回复长度继续生效；其他模型／代理配置不改。

背景不足现在在开启／手动新批排队前提示，不显示假排队。操作：书架 → 管理 / 导入世界书 → 编辑适合公开的条目 → 提供条件选“常驻背景” → 预览确认 → 将该条角色可见范围重新设为“公共背景（所有角色可见）” → 回到事件池生成。若已设关键词并能在世界动态扫描中命中，可保持关键词；不建议把暗线条目公开。缺背景时没有模型调用，单纯提高聊天Token额度无助于这类失败。
