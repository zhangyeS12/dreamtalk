# 聊天与记忆功能体验（桌面0.1.17）

先从旧托盘“退出并停止后台运行”，再打开完整新目录的dreamtalk-desktop.exe。在“设置 → 后台运行”核对0.1.17；使用自启动时显式“保存并更新启动位置”。本轮没有代改自启动或用户存档。

## 长期记忆

- 与角色正常聊天，明确说重要身份、偏好或约定，在“长期记忆”查看原句和记录。自动提取仍优先支持官方DeepSeek的同次JSON；普通台词回复不额外调用API补提取，但原聊天可供关键词召回。
- 同一主题的补充可并存，例如喜欢咖啡和喜欢茶不会仅因同名主题而互相覆盖。明确说“改喝茶，不喝咖啡了”后，由正常回复提出replaces，且本地原句/权限校验通过才建立更新关系。不能保证模型每次都会正确提取或提出更新；记错时可停用。
- 旧核心信息按玩家/角色与身份/偏好/约定分桶，不再全部按最近条目取前几条。特别重要的事实建议置顶；有数量/容量上限，并不是每条永久进入提示。
- 当前问题加同会话前两句分别检索，在本地合并排名，帮助“那个呢”一类追问。仍是关键词检索，明显同义改写可能漏召回。没有新embedding服务或额外提取API，进入正常请求的资料仍占Token。
- 长期条目最多16条/8KiB，历史原句最多4条/8KiB；世界/玩家/角色权限保持。私聊只供对应角色，群聊公开话语供固定成员。详见[长期记忆](LONG_TERM_MEMORY.md)。

## 消息保存后没有回复

聊天底部只为最后一条玩家消息读取恢复状态。

| 状态 | 可以做什么 |
| --- | --- |
| 已保存、尚未开始 | 点击“生成已保存消息的回复（调用模型）”，沿用保存时的Token上限；原消息不重复。 |
| 新版已记录本地校验失败，且没有角色发言 | 点击“重新生成…”，确认当前额度与新增模型费用，创建独立新尝试。原消息/调用/用量保留。 |
| 新版本地任务重启后已可靠标为中断 | 同样由你确认新尝试；重启只改本地执行状态，不自动调用模型，原未知费用预留不清空。 |
| 运行中或结果未知 | 仅查状态。超时、断线、停止生成或结算异常不证明服务商没有处理；旧版没有结束记录的claimed回合也属于未知。 |
| 已有角色回复或后面已有新消息 | 保留已有消息，暂不替换完整回复或补续部分群聊；继续正常聊天。 |

“刷新恢复状态”和“检查回复状态”只读取。准备请求丢响应时，“重试确认同一请求”沿用同一个请求ID，只核对/创建同一份回执；生成前再读状态，不能将不确定的生成自动重放。新尝试内部的选人、路由重试/回退与所有发言继续共享它自己的Token上限。输入框现有草稿在恢复时保留。

## 请你验收

1. 核对正常私聊、无@群聊和指定@仍可用，纯台词及附带事件/记忆路径继续正常。
2. 核对重要偏好跨多次聊天与重启后仍可取用，补充不会误覆盖；明确纠正后查看来源链，群聊成员只更新自己获准的副本。
3. 若自然遇到本地输出校验失败，在最后一条消息确认新尝试：玩家消息仅一条、没有自动重试、费用提示明确，输入草稿保留。不要为了检查而刻意消耗API。
4. 在处理中/断线后刷新，不应自动重发。切会话、角色或世界时旧读取结果不能覆盖新界面。
