# Windows 应用更新

当前公开版本与发行证据统一见[状态清单](PROJECT_STATUS.md#当前基线)，沿用既有完整安装包和固定[更新频道](https://github.com/zhangyeS12/dreamtalk/releases/tag/update-preview)。0.1.48及后续安装清单修复属于历史记录，详见[修复记录](maintenance/2026-10-08-update-manifest-fix.md)；0.1.90的发布证据见[发行记录](maintenance/2026-10-25-release-0190.md)。真实跨版升级仍由用户验收。

**0.1.78增加存档保护与可靠更新。** 本轮补独立完整存档快照、卸载保留、真实存档核对、缺旧清单修复升级及未完成升级回退，见[存档](DATA_BACKUPS.md)和[原记录](maintenance/2026-10-14-save-safety.md)。2026-10-17当前源码五位置改动保留独立更新保护，不占用手动位置，纳入0.1.82发行范围。以下旧包行为按其版本区分，0.1.78源码能力不代表0.1.77下载包已经具备。

## 使用

启动异步检查GitHub预发布频道；新版本在前台书架准备好后提示修复和改进。稍后仅本次运行不再自动弹窗。“不再自动弹窗”保存在本机所有世界共用的偏好中，后续仍检查，书架“世界档案库”右侧出现高亮“新更新”。点击该入口或世界内“设置 → 关于与诊断 → 检查应用更新”可手动打开，取消勾选恢复提醒。

点击更新前保存角色卡、世界书、封面、模型、身份、地点等编辑与聊天草稿。点击后下载并校验签名，等待当前任务完成，正常关闭Core，保留恢复备份，启动完整安装器并前台重启。下载失败或等待超时不会替换当前版本；备份／安装派发失败会尝试重启旧Core，点击“重新连接”恢复界面。更新不新增模型调用，也不自动恢复旧失败任务。

安装位置使用Tauri当前用户固定目录（默认`%LOCALAPPDATA%\dreamtalk`，以后沿注册安装目录升级）。安装器提供桌面／开始菜单入口；只修复官方dreamtalk已启用的自启动，保留`--background`，原来关闭的仍关闭。成功启动后删除清单内旧程序与临时程序恢复副本，保留最近数据快照。不会删除用户世界、消息、卡、封面或凭据，不扫描其他便携目录或下载ZIP。

**旧版首次迁入：** 完全没有更新器的0.1.42～0.1.45仍需一次安装。0.1.78允许已有更新器但缺少清单的程序使用签名完整包修复升级；原未知目录保留。新安装器在旧卸载器和文件替换前备份存档，普通卸载不提供删除数据选项。旧0.1.77及此前安装器如出现“删除应用程序数据”，升级/重装时不要选择，并先保留数据副本。

## 启动失败时更新

0.1.80将更新入口放到Core连接之外，启动失败页也能手动检查更新。可信的失败补丁可由修正版保留原检查点并接续核对；历史快照不作为日常启动必读内容。旧程序未完成的已知更新记录会另外保留，不再一律要求用户手工处理后才能更新。无法确认服务已停止、数据不可读或备份失败时仍取消安装。

旧0.1.78／第一阶段0.1.79的失败页本身没有更新入口，新版本发布不能改变已运行的旧程序。需要先使用本地修复入口或完整新版；正常可进入书架的旧客户端仍可在原更新入口检查。实际下载、安装与重启由用户验收。

## 恢复与限制

**0.1.46／0.1.47安装版清单修复：** 如果更新显示“程序文件与交付清单不符”，使用Release附带的`repair-update-manifest.ps1`。先只读核对安装目录，全部原交付文件符合后才应用；只修复这两版已确认的打包差异，保存原清单，不修改程序或存档。修复后可重新点击应用内更新。其他文件发生变化时工具会拒绝，请退出旧程序并手动安装完整新版。

```powershell
# 将目录换成实际安装位置；不需要Python，不启动应用或安装器
powershell -NoProfile -File .\repair-update-manifest.ps1 -InstallDirectory D:\dreamtalk
powershell -NoProfile -File .\repair-update-manifest.ps1 -InstallDirectory D:\dreamtalk -Apply
```

更新准备只持续本次Core世代，五分钟租约超时恢复准入。关闭普通前台不等于终止正在安装的系统安装器。Windows NSIS不是原子事务，磁盘／权限／安全软件造成的安装失败可能需要手动重跑安装器。

原应用数据目录仍`app.livingworld.desktop`。0.1.78将完整数据快照另存到独立备份位置，手动安装、迁移和应用内升级均先保护存档；内部`updates/recovery/<随机ID>/`仍保留匹配旧程序，`updates/handoff.json`记录版本／入口迁移。原记录ID、聊天/资料/素材及配置核对完成后才开放业务，并持久保存本次核对完成标记。未开放业务的失败升级提供回退入口；完成标记存在后不自动用旧数据覆盖可能的新聊天。回退必须成套处理匹配的程序与停机存档，不是无条件数据库降级或世界分支。

新版能运行而旧文件／快捷方式处理失败时，更新窗口显示未全部处理，保留handoff以便重启重试；不假称“无残留”。源包文件被修改、符号链接／目录联接、非清单文件不会被当成可安全删除对象。用户另存的ZIP不属于本次清理。

签名使用Tauri updater公钥校验；这是更新包完整性签名，**不是Windows发布者证书**，首次安装仍可能出现未知发布者／SmartScreen。仅支持Windows x64完整安装包，macOS／Linux未交付。

## 维护者构建与密钥

本机PowerShell7，已批准私钥存于`artifacts/signing/updater.key.dpapi`，Windows当前用户绑定。不得提交该目录或把私钥写进发布说明／日志。

```powershell
# 已初始化后构建；不启动产物、不运行测试、不发布
pwsh -File scripts/updater-signing.ps1 -Mode Build -OutputName updater-fix-0148 -ArchiveReader C:\Tools\7-Zip\7z.exe

# 用户自行选择仓库外的备份位置，交互输入至少12字符密码
pwsh -File scripts/updater-signing.ps1 -Mode Export -RecoveryFile E:\Backup\dreamtalk-updater-recovery.json

# 换机后同一公钥源码中恢复，交互输入上述密码
pwsh -File scripts/updater-signing.ps1 -Mode Import -RecoveryFile E:\Backup\dreamtalk-updater-recovery.json
```

导出采用PBKDF2-SHA256／600000轮及AES-256-GCM；恢复时校验公钥一致。未执行导出／导入验收。不要重新生成公钥替换已经交付客户端的信任根；遗失私钥和恢复备份后旧客户端无法信任新签名，须重新手动安装。

构建产物在`artifacts/installers/<名称>/`：完整`dreamtalk_<version>_x64-setup.exe`、`.exe.sig`、`windows.json`、更新说明与SHA256SUMS。构建使用已有Core／Web／Desktop链路，所有检查为build-only。0.1.48起必须提供7-Zip归档读取工具，直接解压NSIS并逐文件核对，结果存ARCHIVE_VERIFICATION.json；不执行安装器，摘要不一致立即阻止交付。

## 发布流程

只有获得对应版本 GitHub 发布授权后执行，并事先明确默认分支同步、Release 和频道操作的范围；历史许可不沿用。各版授权与证据从[状态清单](PROJECT_STATUS.md)及[历史索引](history/README.md)查询。

1. 准备版本及`docs/releases/v<version>.md`用户说明。标签和包内的状态文档应标明“构建时快照，最终公开状态见对应Release及默认分支当前状态”，避免将上一公开版本写成不带时间边界的长期现状。
2. 提交并核对源码隐私；默认不运行CI，仅用户主动要求时手动触发并记录真实结果。获得对应发行授权后沿既有build-only流程编译签名完整包，核对静态载荷、签名与SHA256。版本标签须固定到实际构建提交。
3. 创建版本Release草稿，上传安装器、`.sig`、便携ZIP、更新清单、SHA256SUMS及修复脚本；附件大小和摘要核对后才公开版本。
4. 版本资产公开后，最后将该版本`windows.json`上传／替换到固定`update-preview` Release。频道使用更高SemVer、对应完整安装器URL及签名，并核对匿名清单和下载。仅提交源码、仅发布便携包或只创建版本Release都不够。
5. 发布结果补记到`PROJECT_STATUS.md`及其发行记录。在授权范围内将已验证发行提交及后续文档正常合并或快进到默认分支；遇到分叉先处理冲突，不强推。核对远程默认分支包含发行标签，其应用源码与发行提交一致，后续差异仅为预期文档修正。
6. 对照默认分支版本、标签、Release说明、附件摘要及频道，确认交接入口可找到当前状态。已有标签和签名产物保持固定；后补说明写入Release和默认分支文档，不能通过移动标签或替换既有包来“补齐”历史快照。
7. 用户验收跨版本下载／校验／等待任务／安装／Core重启／系统入口／旧文件回收。工程端不把产物存在当作这条链已验收。
