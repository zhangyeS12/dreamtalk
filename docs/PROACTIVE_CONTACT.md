# 角色主动联系与共同邀请

更新：2026-10-07。在线联系、同事由双人联系及在线/离线共用门禁已有代码和历史便携交付。用户目前尚未收到共同联系消息，明确先等待并自行验收；没有收到消息不等于已确认故障，也不构成强制生成或放宽条件的理由。

## 设置入口

进入当前世界，在“设置”手册中找到“角色主动联系”。首次开启须同意后台模型用量；当前世界/玩家独立保存，默认关闭。页面显示收到核心保存结果后的成功反馈，读取失败不等于关闭。

最短间隔默认360世界分钟，可设15～1440。首次开启从此刻建立基线，不补发过去的在线消息；每批日常最多一次。开启只表示允许联系，不保证立即送达。

在线联系依赖世界自动活动；共同邀请还依赖相遇和共同休闲开关。角色必须有真实有效的休息/自由活动。双人必须正在参加 Kernel 已开始的同一次共同休闲，仍符合地点、活动、授权和计划条件；同阵营直接成员已有相识，不必再为取得相识而先碰面。

## 收到什么消息

在线选人先筛选当前计划中实际有效的休息／自由活动：参与角色有已确认资料、已经打开过的本玩家私聊、当前地点／revision与活动连续性，世界运行且玩家可用，间隔和共享未回复门禁都通过。正在进行的同事由双人共同休闲优先，然后按计划ID与候选ID的稳定哈希排序，取首个有效且未使用的活动理由；没有为薇薇安或任何角色设置额外权重，也没有按最近联系次数轮换。相同角色若跨批仍经常处于合格活动，或其他角色不满足前提，就可能连续入选；这不是全角色等概率抽签。

离线恢复走另一条路径：Director在获准角色资料／公共背景／已有活动意图中选择最多一人，可不联系，再由选中角色写台词。它按性格和理由选择，同样没有均匀抽样或轮换保证。不能仅凭角色名字连续出现推断是在线还是离线联系，也不能推算具体存档的概率。

单人发出有真实活动依据的自然邀请；双人在同一个固定双人群中围绕同一目的、地点和活动各发一条台词。不同角色各自的事由不会被拼成共同邀请，不加入第三位角色、委托或虚构成果。回应邀请只是聊天，不自动移动玩家或接受行动。

0.1.40在同一送达事务保存在线邀请与离线`invite_chat`的原话事件，不增加选人／提取API；离线`check_in`问候不记录。此记录只证明收到邀请，未提取的时间应查看原话；不创建Observation、WorldTruth或已接受行动。原话超过1000字的可选事件元数据会省略，聊天仍按原有边界保存。普通聊天的带条件邀约由同次元数据表达，模型仍可能遗漏。

后台生成只使用获准角色资料、实际活动与逐条公开背景，不发送私聊正文、会话摘要、私人记忆或隐藏世界书。遵守既有任务预算，可能产生服务商费用；失败/中断/未知结果不会自动付费重放。

## 红点与等待回复

角色新消息在会话和聊天入口显示未读红点。打开前台可见会话，只确认已经加载的消息位置；保存已读失败时会显示重新确认入口。

阅读和回复是两件事。联系领取、生成、送达都占用门禁；送达后必须由当前玩家在收到联系的原会话里保存更晚的回复，才允许下一次主动联系。阅读、刷新、开关、重启或在另一会话发言都不解除等待。在线与离线、不同角色共用这个限制。

## 暂时没有消息

暂停、忙碌、尚未达到间隔、没有当前有效活动、共同活动尚未真实开始或有未回复联系，都可能使本次机会跳过。程序完全退出或电脑关机后不会执行模型任务；世界时间恢复也不补造共同活动。

可以查看页面的已保存状态、等待回复或任务停止提示。共同联系的实际送达由用户等待并验收，本轮工程端不读取真实存档、不触发联系、不运行应用或模型。

## 实现与边界

首版仅支持同事由双人共同休闲，不是任意多人 Episode。详见[实施契约](proposals/2026-10-04-proactive-contact.md)、[离线消息](OFFLINE_MESSAGES.md)与[当前状态](PROJECT_STATUS.md)。入口为 `ProactiveContactSettings.tsx`，应用为 `application/proactive_contact.py`，持久门禁为 `persistence/contact_gate.py`，迁移为0035。
