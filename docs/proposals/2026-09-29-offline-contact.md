# 已批准切片：后台启动与离线主动联系

用户在讨论后明确要求“没错，按你的建议，开始实现”。这是单角色离线补消息的授权，不扩大为多人 Outreach Episode、关系推进或完整历史世界重建。

1. 桌面默认不自启动、不关闭到托盘；设置可分别启用。自启动使用 --background，主窗口隐藏；托盘打开和彻底退出，单实例保障一个 Core。
2. 离线联系默认关闭，绑定一个指定世界及 Player；应用级同一时段最多一条。切换启用世界会替换旧目标。默认离线6小时，范围1到168小时，是真实经过时间，与 Director 的6小时 WorldTime、聊天 Token 设置分开。
3. 记录应用最后在线时间并冻结合规输入。正常退出、崩溃、关机、睡眠恢复和手动重开共用恢复入口；首次开启只记录基线，不立刻生成。离线过阈值才考虑；世界暂停、Busy、身份变化、无已打开私聊或无合适理由均不联系。
4. 首版目的只允许自然问候/邀请之后聊聊或一起休息，模型可以选择不联系。Director 只选择一个角色、目的和时段；Character 根据自己的角色资料和公共背景写最终台词。公共背景沿用已授权筛选。既有活动仅为意图参考，不能声称离线执行了成果或见到玩家。没有群聊、私聊正文、私人记忆、未知事件或关系数值输入。
5. 选人和台词均不读取或外发私聊正文；仅在本地读取消息标识/位置做去重。剧情发送时间必须严格位于离线区间，真实创建/模型费用记录保持实际时间；消息追加位置、旧历史和真实时间不重写。资料变更和新玩家消息使在途结果失效，不能回答后来才发生的事情。
6. reason key 由系统按绑定 Player 和最近一条玩家互动构造，跨角色去重；未回复上条主动私聊前不再主动问候。一次恢复先持久 claim，再模型调用。失败/中断/无联系永久保留本次结论，不自动重试；开关切换不能重放旧恢复。
7. UI 显示离线联系设置、状态、安全错误及新消息入口。消息显示剧情时间，详情保留真实生成时间和离线补生成标记。未读按实际投递时间，打开并实际可见后标已读。用户可退出和关闭未来联系；已经发出的请求仍可能计费。
8. 复用既有模型网关，选人和台词各有限输出 cap（最高8192或模型更低上限），遵守硬 Token/金额预算和路由。仅后台费用开关被用户明确开启后运行。绝不在关机时调用 API。

按当前 AGENTS，本轮不新增/修改/执行测试，不运行应用、真实 API、用户存档迁移或系统自启动设置；仅静态检查及编译打包，实际恢复体验由用户验收。

自动审批拒绝新增私聊正文外发路径，理由为现有授权范围仅覆盖公共背景。采用更窄的替代：不读取或发送私聊正文，persona/public lore/计划输入沿用已授权范围；本地消息标识仅用于去重，不发给模型。未再次请求扩大数据授权。
