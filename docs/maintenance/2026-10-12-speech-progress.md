# 本地配音自动启动与可查询任务（0.1.56）

日期：2026-10-12。用户反馈一直等待配音，要求本地服务随 dreamtalk 启动，以及真实、明确的阶段提示。本轮仅本地修改与 build-only 交付，不授权 GitHub 发布或工程端合成音频。

## 证据与修复范围

用户任务的本机日志包含模型加载、生成开始和生成结束，说明至少一次推理曾执行到输出；不能据此认定音频已保存或已播放。原实现用一个长 POST 等待整段合成，前端只显示正在配音，无法查询阶段，前台取消也会中断 Core 保存结果。日志另有达到 max_mel_tokens 的警告，音频质量和台词完整性尚待用户验收，不伪称已解决该模型警告。

Core 现在一次性登记任务后立即返回，已接纳的任务经现有 UpdateMaintenance.spawn 计入更新／删除屏障；连接或页面取消只停止前台等待，后台仍可保存已接纳结果。GET 状态按同世界、同玩家、授权消息查询，不重新发送生成请求。退出／超时／断开分别说明原因，旧失败和 unknown 回执不重发。

可选桥接协议 2 提供受本机密钥保护的健康、单次提交、状态及音频读取接口。使用官方 IndexTTS 的 gr_progress 阶段回调显示加载模型、文本处理、第几段合成、保存音频；Core 再报告下载／核对／保存，前端报告准备播放和实际播放。显示真实等待时长，无假百分比；阶段长时间未更新不证明推理仍有进展。播放器启动或缓冲超时给出已生成但未播放的明确提示。

桥接最多保留 1024 个进程期回执，已生成音频缓存最多 96 MiB，Core 仍按原 256 MiB 缓存／32 MiB 结果／每日次数限制保存。回执满时拒绝新提交，需在完成当前任务后重启本地服务，不自动清除回执再生成旧任务。

## 本地服务生命周期

Tauri 读取当前存档中“任一世界开启本地默认地址配音”的布尔需求，在 Core 启动后独立启动已配置的模型环境；设置中保存开启时也启动。后台启动不弹终端、不阻塞书架，不新增系统服务或注册表项，首次任务才加载模型。退出 dreamtalk 停止它持有的子进程树，托盘保持运行；外部启动的服务只读取状态，不擅自终止。

模型目录只保存在本机配置。设置增加选择目录、检查并启动；本仓库部署布局允许在包的有限父目录中发现已完成的独立环境，不包含硬编码个人目录。管理默认 127.0.0.1:7861；自定义本地地址仍由用户独立管理。密钥读取现有本机文件并经既有世界作用域凭据登记／native vault 传入 Core，不经前端回传或写入公开文件。旧桥接服务仍在运行时提示先停止，不抢占端口或重放任务。

## 成熟实现复用

复用现有 Tokio 子进程、Tauri 2 和 dialog 2.8.1（MIT／Apache-2.0）、FastAPI／asyncio 和 UpdateMaintenance 的跟踪任务机制；不引入队列服务、Torch Core 依赖或另一个桌面框架。阶段回调核对已安装官方 IndexTTS 源码 d9e41aac89fd00b3d71497fddb287b7f24613712 的 infer_v2_5.py；仅调用其接口，不复制模型实现，模型许可仍为 Bilibili Model Use License。
