# Android 与 Windows 的现行差距

以当前 Windows 工作区源码对照，不把公开 Windows 安装包当作最新源码。Core 对照覆盖 392 个共有 Python 文件，其中 386 个字节一致；6 个差异为宿主启动、更新维护、原生请求上限桥接、媒体路由、安全保存和固定语义检索后端适配。另有 Android 专用模块。HTTP 生成契约一致，API 客户端的差异是把未选择的初始地点空字符串规范化为省略字段。完整文件清单见 ../artifacts/chat-parity-20261108/source-comparison.json。源码相同不等于手机性能、模型效果或存档迁移已经验收。

## 已有实现，继续保留

私聊、群聊、流式回复、重试／恢复保护、同一 attempt 的费用与 Token 上限、知识权限、私密片段、动态角色卡、记忆与世界书、角色活动和主动联系的 Core 已迁移；模型、配音、图片、后台、备份、世界时间、角色活动、主动联系和世界动态等设置入口已存在。校园示例可从世界列表创建。不是从零重做这些能力。

“我”的世界资料页通过 ProfileEditor 嵌入 PlayerPersonaEditor，已有专用玩家角色卡导入、预览和确认，不能登记为未实现。

## 实现存在但手机证据尚不足

后台会话、通知和开机恢复已经实现，不属于缺失后端。OriginOS 省电／锁屏／Doze、进程回收和恢复、通知点入正确身份、停止后不生成、耗电发热及长期后台主动联系仍需单独验收。“成功打开运行”只确认启动场景。

系统文档存档导入导出、Windows 与 Android 的完整存档往返、升级数据连续性、真实 API 配音／图片和长聊天效果也不能由源码／编译推断通过。

## 推荐推进顺序

按用户当前决定，先在本机验收聊天一致性与长期记忆，按具体反馈修正；等用户明确要求再发布。通用资料、完整世界管理及静态卡片库／卡包保留为剩余差距，不由本表自动授权开发。vivo 的后台通知、长对话内存和流畅度留待手机阶段验证。

具体发行与验收以[状态清单](PROJECT_STATUS.md)为准。本表不触发发布、模型调用、真实存档诊断或额外功能授权。
