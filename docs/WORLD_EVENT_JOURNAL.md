# dreamtalk：聊天获知与世界动态

聊天列表顶部的“世界事件”分别展示聊天获知、亲历记录与世界动态。当前版本与验收边界统一见[状态清单](PROJECT_STATUS.md)。事件是有时间和来源的信息；旧记录不代表角色现在仍在做同一件事。

## 聊天获知

四类已配置文本协议（兼容Chat Completions、OpenAI Responses、Anthropic Messages、Gemini Interactions）共用可选JSON注释提示和本地校验，不要求原生JSON Schema。角色可在正常私聊或群聊回复的同一次调用中附带最多3条事件候选。具体活动、未来计划、传闻、邀请和计划变化才应记录，寒暄、心情、习惯、假设和重复闲聊可以不记录。没有另外调用模型分类，但提示、历史记录和元数据仍占正常聊天预算。

例如“我明天下午想去商店购物”可以记录为计划，而不是已经购物。列表保留角色、原话、获知的现实时间、获知时的世界时间，以及原话中的事件时间；没有明确时间就显示未明确，不把“明天”猜成某个现实日期。以后明确改变同一计划，可以关联旧记录；旧原话仍保留。批注／纠正不会改写原聊天，移除只隐藏该条事件记录。

不会替换已配置模型；具体型号／代理能否稳定返回注释仍按场景验收，旧聊天不付费补录。在线主动邀请和离线`invite_chat`在送达时按已验证目的保存原话，不新增提取API，`check_in`问候不记录；超过1000字的可选邀请元数据省略。完整普通台词也可成功保存，该次没有新的事件或长期记忆条目，不额外调用API补提取；完整JSON代码块按同一规则解析。元数据校验失败可忽略该条记录，不发起额外付费修复；空正文、截断或损坏的JSON走回复错误流程，不把内部字段直接显示为台词。共用入口为`services/core/src/livingworld/application/chat_event_annotations.py`。

原句必须真的出现在回复里，来源和旧记录引用按当前世界、玩家、发言角色及会话核对。去重采用有限来源／原句指纹，不额外调用语义裁判。模型仍可能漏记、误归类或说错事实，用户可批注和移除；元数据的本地校验不等于语义事实核实。

具体的条件邀约（如“收工后若还早就来喝牛奶；太晚就别等”）属于邀请，保留整段条件／取消分支，不把修辞或纯假设记录为事实，也不写成确定赴约。提示已明确这类区别，但同次模型元数据仍可能遗漏或不合规，不能保证每句话都被自动记录。

“亲历记录”现在独立于聊天获知，折叠区域保留原来按玩家观察授权的记录。相同角色在不同世界时间再次开始休息，会生成不同真实活动记录；同文不代表同一事件。查询按event ID聚合同一玩家的观察，不按文案合并不同活动。角色另外读取自己的亲历资料。聊天自述不是世界事实，也不新增角色记忆、观察授权、物品或关系。

## 世界动态

先在当前世界确认世界书，并逐条设为“公共背景”。打开“设置 → 世界动态事件池”，首次开启确认后台模型用量授权。该功能每世界默认关闭；与角色自动活动、离线联系分别开启。只发送已公开背景标题、正文、世界名称和已有动态标题，不发送私聊正文、隐藏世界书或私人记忆。

每次生成10条动态存入隐藏事件池。按已确认规则，以候选可用世界时间先后填充最多5条进行中；另外5条保持未发布，绿／灰腾位后从合格储备中补入，红继续占位，替代原15～45分钟随机发布节奏。若候选尚未到时间，进行中可以少于5条。模型只在生成整批时调用，补位不新增API。候选可用时间在本批前6小时内，过期窗口在12～24小时世界时间内；默认立即可用、24小时过期，提供的窗口仍严格校验。真正发布时记录当前世界时间和现实生成时间，不补造错过的历史公告。

每条右侧由你操作：红色“未经历”、绿色“已经历”、灰色“跳过”，同时有文字和键盘按钮。模型不判断你是否经历。达到最近整批10条的80%（8条已经历或跳过）时自动生成下一批，每批仅触发一次。旧的未处理动态继续保留，未处理总量有100条上限；取消或过期候选不会被当作已经历。

绿／灰消息进入可展开的历史。旧版已经发布过的十条保留原账本及标记，界面按发布时间先展示最早5条未处理项，其余在处理后依次显示；后台不再扩大满员窗口。历史改回红色也保留已发布事实，可能形成待展示队列，不撤销旧公告。未发布候选不会进入角色公共动态上下文。

如果池已无可发布候选，但仍未达到8／10，可以在设置显式点击“生成新一批（调用模型）”；出现中断、背景变动或模型错误时也在这里处理。刷新事件／刷新状态只读取，不调用模型。批量生成输出不合规时不会自动花钱修复或重发。

程序及Core运行、世界未暂停时才会发布。关机后不生成，恢复时不把错过的公告全补出来；未过期候选继续，过期候选取消。世界暂停不推进发布。此功能与Director的6小时活动批次及50%失效重规划分别治理，但模型调用复用当前既有路由和财务预算。

动态可以是活动预告、公共通告、传闻或探索邀请。Kernel记录的是“这条公共消息已发布”，不证明传闻真实、活动已完成或玩家已参与；绿色标记也不改变物理世界。可以点“聊聊这件事”选择已有会话，核对草稿后手动发送。

## 反馈、来源与验收

背景不足在开启／手动新批排队前提示，不显示假排队。世界书条目须当前已确认、公开、启用并满足触发条件；可公开的稳定设定可以设为常驻背景，经预览确认后再明确公开。不要为消除提示公开暗线；缺背景时没有模型调用，单纯提高聊天额度不能修复前提不足。

格式、空回复、截断、超时、额度和容量分别提示，不自动增加额度、修复或重放。事件提示包含完整JSON示例，本地仍校验恰好10条及时间窗口。后台状态与读取恢复见[状态反馈](BACKGROUND_TASK_FEEDBACK.md)和[生成／读取恢复](GENERATION_READ_RECOVERY.md)。

“聊天获知 → 来源原话 → 查看原文前后文”显示源消息及前后各最多3条，保留来源时间、批注及编辑状态。来源查询按原会话当前权限读取，不把自述改写成事实，也不广播未知共同休闲；见[来源回看](SHARED_LEISURE.md)。
