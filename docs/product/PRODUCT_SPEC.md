## 文档状态与适用范围

- 阶段：Stage 0 — 产品和架构定义。
- 本文记录已冻结的产品规则，以及尚待澄清的边界；这些要求不代表功能已经实现。
- C-001 交付工程仓库与设计文档骨架，不实现 Agent、Director、数据库业务或 UI 功能，不决定应用框架、数据库或其他实现技术。

## 冻结规则

### FR-01

dreamtalk 是持久化、事件驱动的多角色 AI 世界，不是普通聊天机器人。

### FR-02

Director 负责时间、地点、世界事件、角色活动、角色相遇、关系变化和宏观剧情调度。

### FR-03

Character Agent 主要负责自己拥有的记忆、人格表达和与玩家对话。

### FR-04

世界真实事实、Character Knowledge 和 Player Knowledge 分离。

### FR-05

后台发生但玩家不知道的事件不能直接展示给玩家。

### FR-06

玩家任意时刻只能存在于一个物理地点。

### FR-07

关系后台存在，但不能向普通玩家展示数值。

### FR-08

玩家具有 Busy / Available 状态。

### FR-09

Busy 时 Director 不得发起非必要主动联系。

### FR-10

Available 时 Director 可以安排一个角色或一组角色主动联系。

### FR-11

同一个主动联系理由最多主动发送一次；玩家未回复不能持续催促。

### FR-12

多角色主动联系必须围绕一个统一目的，形成 Outreach Episode。

### FR-13

Director 使用批量 World Plan + Event Reservoir，禁止为每个普通小事件单独调用 LLM。

### FR-14

Event Reservoir 中的候选事件由传统程序激活、延期或取消。

### FR-15

Planning Window 耗尽或大量计划失效才触发 Replan。

### FR-16

Director 有用户可配置风格面板。

### FR-17

AI Character Builder 可以联网研究角色并生成带来源的角色 Draft。

### FR-18

AI World Builder 可以联网研究作品/世界并生成带来源的 World Draft。

### FR-19

自动生成内容必须经过 Draft → Preview → Commit。

### FR-20

支持 Character Card V2/V3、PNG/JSON 和 Lorebook 导入。

### FR-21

UI 必须面向非技术用户，高级模型参数隐藏到 Advanced/Developer Settings。

### FR-22

世界支持 Checkpoint 与 Timeline Branch。

### FR-23

Developer Mode 能查看 Director、Agent、Memory、LLM 使用等决策 Trace。

### FR-24

产品必须记录 Token、Latency 和 Cost，并支持预算与模型路由。

## 已确认的产品补充决策

以下是产品负责人后续明确确认的交互约束；它们补足相应待确认问题，不改写上方 FR-01 至 FR-24：

- **聊天体验（P-07、P-16）：** 产品核心是角色扮演聊天。私聊和群聊可以跨物理地点，聊天不移动 Player。世界事件入口置顶于聊天列表；只显示当前世界绑定 Player 已获知的事件，并用于拓展聊天话题。每个世界导入的角色卡/世界书版本彼此独立；更新必须在当前世界预览确认。
- **角色身份和通讯录：** 已导入角色卡先作为当前世界联系人可见；首次打开聊天时才创建或复用运行时 Character。新世界 Player 默认从“家”开始。玩家的通用自我描述与世界专属身份分别保存；冲突时世界专属身份优先。
- **群聊轮次：** 一条玩家消息开启一轮有界群聊；同一轮由独立于 Director 的群聊调度器依据角色卡性格和共享对话选择下一位发言角色。玩家 `@` 某位参与角色时，该角色是下一位发言者。Director 仍只负责批量世界计划和世界级调度。
- **公共背景与暗线：** 世界的大局观可作为所有角色共同知道的创作背景。世界书中可能含暗线，导入后默认不向角色聊天上下文开放；只有当前世界逐条明确设为公共背景的内容可提供给角色。公共背景素材不自动成为运行世界的 WorldTruth。
- **群聊可见性：** 群聊中的消息一经持久发送，就视为该群所有参与角色均已看到，不以是否发言或是否轮到其回复为条件；角色随后私聊也可参考自己曾参与群聊的消息。看到某人的说法不等于承认它为真实 WorldTruth，也不自动创建 CharacterBelief 或 EpisodicMemory。
- **群聊 Token 硬上限：** 设置值约束一轮内所有选人和角色回复的输入及输出 Token 总量，所有路由候选与物理重试均计入。每次物理模型调用前，系统须为输入做保守预留并为输出留额度；用量无法可信预留时不得启动调用。达到上限后不再启动下一次角色发言。预留与真实用量的差额按已确认账本事实结算，不得重复累计终端快照和用量更新。
- **台词确认边界：** 角色台词经系统校验后直接发送，不逐条要求玩家预览；持久创作内容仍须 Draft → Preview → Commit。

后续澄清应记录结论与对应问题编号；涉及冻结规则变更时，应明确提出变更并由产品负责人确认，不能通过示例或实现默认值隐式变更。

## 已实现的内容编辑与摘要研究生成（2026-09-28）

设置支持手动创建/编辑角色卡和世界书。用户显式点击联网生成时，搜索组件获取有界网页摘要，现有模型服务整理字段、出处判断、冲突与不确定信息；结果先填入可修改草稿。角色卡开场白、情境与对话示例标记为创作建议。Preview 展示后由当前本地用户确认，Commit 仅影响当前 World 的 authored 内容，不直接写运行世界事实。世界书默认隐藏，保存后再逐条公开；更新重新确认可见范围。

生成 request ID 有独立持久回执，重复请求/检查结果不再次 dispatch；中断不自动重试，新的生成是新的模型调用。普通手动编辑不需要 API。此切片对应 FR-17/FR-19 的角色卡与世界书资料辅助，不代表 FR-18 的完整可运行 World Builder 已完成；来源支持判断由模型提出，尚无全文核验/持续更新。见[实现与复用边界](../research/2026-09-28-content-builder-reuse.md)。

资料生成使用独立任务预算，不读取聊天的每轮 Token 额度；单次输出受模型配置与 8,192 Token 双重限制。可信输入上界仍在每次物理调用前检查，retry/fallback 共享同一有界生成预算并沿用账本与金额预算。任务容量的保守预留不等于实际计费 Token；真实提供商调用与资料质量仍由用户验收。

资料保存分为打开预览和明确确认两步。长草稿点击预览后自动定位到预览或错误；预览上下提供确认/返回编辑操作，保存成功显示可见通知。字段缺失、连接/版本错误及预览容量限制不会通过静默禁用或屏幕外反馈掩盖；失败保留当前草稿，不自动重新调用模型。


## 已确认会话记忆摘要（2026-09-29）

用户接受工程建议继续推进可核对、可确认摘要。当前实现为本会话的持续摘要：使用已配置模型，将上一确认摘要与后续原文按批整理；用户编辑、预览来源、确认保存，后续角色回复才参考。用户修正形成新版本，保留来源与旧内容。它不替代角色独立私有记忆，不自动改写世界事实；跨会话、自动遗忘、Director 等仍为后续范围。编译完成不代表运行/隔离/迁移验收已经通过。


## 已获知事件与对话连接（2026-09-29）

现有世界事件话题入口补充受支持亲历事件的中文详情；点击后只填写可编辑草稿。单聊/群聊的发言角色分别读取自己有限的亲历事件，玩家可见内容与角色可见内容独立授权；没有记录时不编造，也不把通信自动变成世界知识。本轮没有自动世界活动/主动联系，计划消费与重规划仍是后续范围。

## 已批准日常 Director（2026-09-29）

用户明确批准[推荐方案](../proposals/2026-09-29-director-runtime.md)。当前代码覆盖持久有限批量规划及基本 Kernel 日常开始/已有地点移动，启用每世界默认关闭；此前“Director未实现”的状态由此补充，不能扩大为完整世界生命周期已交付。P-17 已明确本切片的 candidate授权/CAS/重叠冲突取消与新旧批衔接；其他 action、事实更正及主动联系 P-03/P-04 仍未冻结。首版不会补造错过的离线活动，只有真实提交且被获知的事件进入对话。
