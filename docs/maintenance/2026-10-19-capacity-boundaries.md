# 六项容量边界优化

## 范围与实现

用户根据源码审查批准优化六项问题，并单独批准仓库外合成数据／模拟服务的隔离回归。沿用现有 React、FastAPI／Pydantic、SQLAlchemy 和内容预览流程；没有新增依赖或数据库迁移，不修改权限、费用、任务重放及真实用户数据。

| 原边界 | 当前实现 |
| --- | --- |
| 导入可到10000条，编辑稿限制128条 | 已有内容每页32条，修改按字段／来源条目ID提交；后端保留未加载内容并合并完整预览。修改请求最多4MiB，条目总量与导入一致；旧接口兼容。 |
| 活动／在线联系完整输入超过64KiB即停止 | 复用本地 UTF-8／JSON 引用预算，保留角色身份、来源及合法路线；原卡不修改。在线单个坏候选不拖停其他候选，准备恢复不重置真实任务回执。必要身份仍无法容纳时保留拒绝保护。 |
| 公共背景总数超过512或单条条件超过16KiB即整批拒绝 | 每次流式读取512条，按原授权、触发及排序选择本次16条／12KiB以内背景，同时核对JSON转义后预算；单条异常仅排除该条，不截断并重新解释条件，不以秘密补位。 |
| 会话超过512个即未读接口失败 | 首批返回数据库全局汇总，明细每页128个；客户端继续读取并拒绝重复游标。旧接口保留完整读取兼容。 |
| 角色版本追踪最多128层 | 元数据递归查询与已访问ID检测，正常长链继续解析，真实循环或无效来源拒绝，不读完整卡片追踪。 |
| 在线联系只看前64条配置 | 保存进程内扫描位置，后批继续并循环；持久理由、未回复、计划及计费回执不重置。 |

输入预算入口为 `application/input_budget.py`；编辑为 `application/content_editor_pages.py`、同名HTTP模块及前端 `contentEditorPages.ts`。其他入口见[交接](../../HANDOFF.md)。API为增量扩展，TS请求／响应及校验继续由Python源生成。

## 工程证据

定向检查使用仓库外临时 SQLite、合成资料、模拟服务和内存 DOM，隔离 APPDATA／LOCALAPPDATA、缓存、模型离线环境与临时目录。没有真实模型、凭据、已安装应用、安装器或真实存档操作。

- Python覆盖150条世界书与超长原文、跨页保留／预览确认、隐藏背景隔离、550条公共背景、129次版本替换与真实循环、超过513个会话、65个世界配置、长角色规划与在线实际合成投递／去重。
- 前端覆盖跨页编辑保留、稀疏修改、未读连续分页／重复游标保护及删除末页后的返回；相邻内容、ProductApp、离线反馈和客户端兼容一并核对。最终计数见下方回执。
- 静态核对覆盖Ruff／格式、ESLint／TypeScript、68文件Pyright、生成一致性、文档链接、隐私扫描及Git差异。

首轮发现分页响应未将UUID转为字符串，已修正；排序夹具改为明确的源排序值；旧离线夹具改为在首批稳定注入坏候选，保留原断言。扩展投递检查同时保证领取与投递按相同引用预算比较来源，未通过放宽校验取得成功。

最终回执：31项Python定向检查通过，另对其中2项补强旧准备状态／真实失败回执后单独复核通过，不重复计数；39项前端／客户端检查通过。Ruff／格式、TypeScript／ESLint、68文件Pyright、契约生成一致性及Git差异核对通过；1152个本地文档链接无断链，1011个源码文件隐私扫描无发现。外部链接仅计数。Python保留一条既有Starlette／AnyIO弃用提示。

新增确认提交检查曾因夹具新建了另一份预览服务而返回 `preview_expired`，已改为沿用创建预览的同一服务；客户端重复游标检查核对公开 `code` 字段，而非通用异常文案。一次自动权限审批超时未执行，按工具允许重试后完成隔离检查。以上不属于真实应用或模型运行证据。
