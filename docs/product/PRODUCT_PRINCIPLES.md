# dreamtalk 产品原则

本页是设计判断索引，不维护实现进度。规则编号保留在[原始FR规格](PRODUCT_SPEC.md)，后续批准行为以[现行产品约定](../../PRODUCT.md)为准，实现／验收以[状态清单](../PROJECT_STATUS.md)为准。

| 原则 | 设计判断 | 原始依据 |
| --- | --- | --- |
| 世界存在，交流呈现 | 世界活动与角色表达分工，用户通过获知和亲历了解变化；普通界面围绕聊天。完整离线演化仍是未实现愿景。 | FR-01～03、FR-06 |
| 发生与知情分开 | 世界事实、角色信念与玩家知识隔离；权限先于提示，后台事件不自动向所有人公开。 | FR-04、FR-05 |
| 关系通过体验表达 | 不向普通用户显示关系数值；问候和自述不能证明实际成果或新关系。 | FR-07 |
| 联系尊重用户 | Busy／Available、合法理由、同事由去重及未回复门禁共同约束；不开启就不后台生成。 | FR-08～12 |
| 规划有界且可验证 | 批量提案、确定性验证执行；不逐小事件调用模型，不把候选或文本当权威事实。 | FR-13～15 |
| 创作保留用户控制 | 研究、来源、草稿和确认分开；运行台词与持久创作采用各自批准流程。 | FR-17～20 |
| 普通用户免维护 | 用户决定更新、付费和历史状态切换；工程端承担安装、存档及故障处理，界面不暴露技术负担。 | FR-21及后续用户决定 |
| 证据与费用诚实 | 不把构建当验收；不重放未知收费任务，不按品牌猜容量；诊断与开发权限不扩大到普通界面。 | FR-23、FR-24 |

Director风格、完整时间线及其他未冻结方向查状态表，不能从早期原则推导为当前已实现功能或自动开发任务。具体数值、入口和异常规则只在产品约定及相应模块手册维护。
