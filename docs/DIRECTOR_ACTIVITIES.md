# 世界自动活动体验说明

本版实现已获批准的 Director 批量规划与基础角色日常。它还不是完整自主世界。

1. 关闭旧窗口，打开本包 dreamtalk-desktop.exe。旧数据会按原流程增量升级到0025；请勿再用旧程序打开已升级存档。
2. 在当前世界选择自己的身份；通讯录打开要参与的角色聊天，使已确认角色卡实例化。没有运行角色时显示明确提示。
3. 设置 → 世界自动活动 → 开启 → 首次确认后台模型用量。采用当前已配置模型，各提供商使用同一治理，不只支持DeepSeek。
4. 等待规划状态完成。角色可以开始休息、工作或自由活动；已有多个地点时可移动。只有“家”时先在家活动，不虚构新地点。
5. 查看聊天中的世界事件：只显示自己实际获知的变化。点已有“聊聊这件事”自行发送，或问角色近况；角色只参考自己的亲历记录，开始活动不保证任务成果。

每批6小时世界时间；少数偏差取消对应候选，至少2条且达原批50%失效才提前续批。输出上限为模型cap与8192的较小值，独立于每轮聊天额度，仍服从既有硬Token/金额预算。规划失败/空输出/重启遗留不会自动付费重放；“重新规划”明确开启新任务。

每世界默认关闭。暂停后不执行候选或开始新批；已发给模型的请求可能仍产生费用。关闭自动活动阻止未来工作，已提交事件保留，迟到模型结果不会重新启用。应用关闭时没有AI后台进程。返回时不补造已经错过的活动：尚在有效时段的候选可按当前时间开始，已过结束时刻的候选expire；旧窗口外不生成未规划的历史。

当前容量：最多16名已放置角色、32个地点、64候选/批，必要输入64KiB；超出时明确提示并停止，不静默漏掉角色。输入仅取已接受角色卡的描述/性格/背景和同世界位置；本批没有世界书背景、私聊、摘要或私人记忆输入。未来计划没有普通UI浏览入口。

日常事件只表示“开始活动”及可选位置变化；结束计划时段只释放占用，不宣称完成了工作或取得成果。尚未实现主动联系、剧情相遇、关系推进、丰富地点编辑和完整离线活动重建。下一步按明确的目的/去重规则接主动联系。

本轮只做源码复核、Ruff/ESLint/TypeScript和编译打包，没有运行测试、迁移、应用或真实API。实际开启、计划质量、事件与知情隔离、暂停/关闭/恢复仍请按你的体验验收。
