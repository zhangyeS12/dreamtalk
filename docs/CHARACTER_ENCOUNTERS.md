# 角色相遇与经历召回（桌面0.1.25）

角色现在可以把真正碰面的经历带进之后的聊天。例如铃和艾莲都在咖啡馆休息，日常计划安排短暂问候；到时双方仍在场且活动有效，才记录碰面。仅同地点、聊天一句设想或未来计划不会自动产生共同经历。

## 如何开启

1. 从旧托盘选择“退出并停止后台运行”，打开完整character-encounters/dreamtalk目录里的dreamtalk-desktop.exe，保留core目录。在“设置 → 后台运行”核对0.1.25；使用自启动时在新版显式保存更新启动位置。
2. 通讯录打开至少两名角色的私聊，在设置给角色指定初始地点，准备合适的活动地点。
3. 在“世界自动活动”开启已有日常规划，再在下方“角色相遇”点击“允许角色相遇”，首次确认同批后台用量。
4. 开启等下一批正常六小时规划，不因保存立即调用API；刷新状态也不调用。已开启Director的正常后台批次仍按原授权自动运行。模型可能合理返回空相遇列表，不保证每批碰面。设置时世界已暂停，则恢复后才执行活动。
5. 之后正常问角色“最近遇到谁了？”或提到对方。回答只依据本人已有观察；近期与较早相关经历可一起召回，仍在最近128条词法候选、最多12条/8KiB内。不会额外调用API判断记忆。

## 时间、可见范围和费用

- 同一批可选最多8次碰面，两人当时必须在相同已有地点、实际处于对应的休息或自由活动，不能在工作中强行打断。相遇只打招呼，不移动玩家或角色，不自动改关系、创建对话或完成任务。
- 同一对角色在连续6小时世界时间内最多一次；最多5分钟有效窗口，且不能越过双方活动结束。错过、地点/revision变化、暂停或开关取消时，不补造过去的相遇。
- 双方各自保留见闻；实际在场且获准的其他主体可以目击。群聊成员不会自动知道后台碰面；你不在场时不会直接收到全知世界事件。角色在自然聊天中说起时，沿已有聊天获知事件路径记录，既有模型提取规则仍决定是否形成条目。
- 每次碰面不调用模型。相遇和日常共用一次规划，同批JSON可能增加输出Token，仍遵循现有独立后台预算；正常聊天输入/输出仍按实际用量计费。开启后不加入其他角色私聊、私人记忆或隐藏世界书输入。
- 关闭取消待执行候选，保留已发生的见闻。关闭Director或退出应用停止后续执行，迟到规划不能恢复关闭功能；已开始的模型请求仍可能产生用量。相遇取消不计入日常半批失效的提前重规划门槛。

## 数据与验收边界

新增0033增量迁移，只创建相遇同意设置和有限候选两张表，不改旧表字段顺序，不回填历史。正常启动由现有Alembic流程升级；不要用旧schema程序打开升级后的同一存档。Kernel同一写入事务复核双方状态并提交CharactersMet v1、event_occurrence观察、候选结果、ResolveEncounter幂等回执；重复领取返回已有结果，不重复产生事实。账本重放校验时段、参与者、活动来源、revision与冷却，不改变位置或关系。

本轮只做源码审查、lint/format/type、编译与包内静态字节检查，没有运行自动测试、桌面/Core/模型或真实存档迁移诊断；新功能运行效果待你验收。可重点体验关闭相遇时原日常是否照常、开启后一段有效日常的碰面是否能分别提及、离开地点/暂停后是否避免编造、重启后已发生记录是否保留。相遇具有可选性，没有碰面本身不等于失败。
