# 已批准：存档保护与可靠更新

用户在讨论后明确“批准，现在优化”。批准的是本机完整存档保护与应用内更新，不是云同步、世界分支或新的世界演化功能。

- 保持 `app.livingworld.desktop` 及原存档位置；卸载仅移除程序，清除数据在应用内独立确认。
- 独立备份默认位于 `%LOCALAPPDATA%\dreamtalk-backups`，允许用户通过系统文件选择器指定其他位置；位置登记也在独立目录，重装后仍可发现。
- 有持久变化时每30分钟备份；保留近7日每日备份及最近3次升级/迁移/安装前快照，手动与恢复前快照不静默删除。
- SQLite backup API 生成包含已提交WAL的完整数据库，成套保存素材、身份和配置；不包含模型权重、可重建缓存或Windows凭据正文。不调用模型、不自动上传。
- 恢复先校验、保留当前数据、停止Core后替换，核对实际读取的库；恢复后须确认继续，旧生成任务不自动重发。已知无正文调用回执、每日计次、预算和费用记录不随剧情回退；后台活动、动态和主动联系需用户重新开启。
- 提供备份、导入/导出 `.dreamsave`、恢复、位置选择及独立清空入口。清空不创建新的私人内容备份；备份是否一起删除由用户明确选择，无正文财务保护记录保留。
- 启动发现旧备份而当前库丢失/异常为空时，显示恢复入口，不能静默建立一个空世界来冒充原存档。用户明确删除最后一个世界不视为存档故障。
- 应用自动检查更新，用户点击后自动下载、验签、等待任务、备份、安装和重启。缺少旧清单走签名完整包修复，不据此信任未知旧文件，也不清理未知旧目录。
- 新版核对原记录稳定ID、素材与配置后才开放业务；失败保留并恢复升级前材料，不能只看程序启动成功。新版已产生新数据后禁止自动用旧快照覆盖。
- 继续用户测试与最终验收；工程端只做静态/格式/lint/type/必要编译。本轮不授权打包、发布、安装、模型调用或真实存档测试。

成熟实现复用与许可见[调查](../research/2026-10-14-save-safety.md)。
