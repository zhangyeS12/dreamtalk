# 设置状态与世界书公开范围修复（桌面 0.1.16）

## 已设置地点，为什么仍说没有角色

地点确认是成功的，但此前因没有已放置角色而停止的规划保持待处理。刷新只读，不能偷偷发起新的付费任务。新版用已经读取的当前身份角色目录核对初始地点：已确认时显示“角色初始地点已确认，上一批规划仍待重新开始”。点击“重新规划（调用模型）”明确开始新批次；暂停世界需先恢复。它不会移动玩家或重复设置角色。

## offline_reason_used

这是同一离线联系理由已处理的正常跳过，设置仍开启。新版显示普通原因说明；刷新不会删除去重记录，也不会再次发送。继续与角色交流，下次满足离线时长、可用状态及其他条件的恢复会再判断，仍可能决定不联系。不会自动重试旧模型任务或持续催促。

## 公开后更新又变隐藏

旧版任何世界书内容更新都生成独立新版本，旧公开授权不随新版本保存；下拉框保存还会把页面拉到顶部。新版修复：

- 下拉框选择后立即保存，再只读核对当前版本；成功提示留在该条目旁，无需另点内容编辑保存。网络响应丢失只核对，不自动重写；可点击“刷新可见范围”或“刷新已保存内容与范围”。
- 原生界面编辑在服务器记录条目对应关系；同世界替换保存的一笔事务中，只保留有明确原条目、全部正文/标题/关键词/启用状态/完整触发条件及兼容字段未变的原授权。书级扫描条件也必须未变。提交响应返回真实公开范围。
- 新增、修改或无法对应的条目保持隐藏；从文件替换仍需重新确认。不会按同名或相似文字猜测对应，也不会从历史版本回填授权。正在内容编辑、预览或替换时先完成保存，再调整范围；范围保存期间禁止交叉操作。
- 旧版已经重置为隐藏的条目需要你在当前版本重新公开一次；程序无法区分用户主动隐藏与旧版重置，不批量恢复。

公共权限与触发条件是两件事。世界动态生成要求至少一条公开、启用且满足后台触发条件的背景。如果需要稳定的通用设定，编辑适合公开的条目为“常驻背景”，先预览并确认更新，再设为公共背景，然后显式生成事件。来源里不支持的高级条件不会被跳过后无条件外发。

## 运行与验收

退出旧托盘“退出并停止后台运行”，直接打开完整的 `artifacts/portable/settings-feedback/dreamtalk/dreamtalk-desktop.exe`，保留同目录 core，无需再解压已有完整目录。需要自启动新版时，进入“设置 → 后台运行”显式保存更新启动位置。

工程端只做源码、diff、Ruff/ESLint/TypeScript、编译与包文件核对；不运行自动测试、GUI、真实模型调用或读取/修改你的存档和密钥。没有新存档迁移，沿用0030。用户验收：地点确认后的旧规划提示、离线跳过原因、公开后重开、未改内容更新保留范围、改内容隐藏并重新确认、取消编辑和事件池生成。
